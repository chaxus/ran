# Changelog — 2026-10-17

## ranui

- Treat input and select labels as plain text on every update.
- Synchronize dynamic input type, disabled, value and numeric constraints with the native control. Attribute changes now update form submission values, including value removal.
- Relay native input validity (including email and number constraints) to the associated form and accessibility state.
- Read raw SVG imports as text instead of exporting a file-result wrapper.

## ranuts

- Resolve declaration aliases and relative imports for Bundler and NodeNext consumers. Build declarations exclude tests.
- Mark ESM modules as free of import side effects, preserving IIFE initialization. A packed-package check verifies consumer types, ESM runtime imports and a 1 KiB gzip budget for a single color helper import.

## Alpha cleanup (breaking)

- Retire `ranuts/node` and its HTTP, WebSocket, file and CLI wrappers; use native Node APIs or a maintained server framework. Remove their build targets, fixtures and obsolete documentation.
- Remove `memoize`, `timeFormat`, `timestampToTime`, `isClient`, `md5` and `FMT`. See the [alpha migration guide](https://ran.chaxus.com/src/ranuts/migration/) for replacements and return-value differences.
- De-duplicate script loading by exact type and content, fixing LF/CRLF collisions caused by the former MD5 normalization.
- Preserve source module boundaries in ESM output so unused initialization can be removed independently of entry-point chunk sharing. Keep standalone IIFE browser bundles.
- Keep one lazy `EventManager` implementation in ranuts and forward it from ranview; retain listener cleanup and reconnect coverage.
- Remove unused SVG sprite sheets, private ranui helpers and duplicate barrel registrations. Keep standalone component bundles and scratch registration.
- Publish ranui declarations from runtime sources only, excluding tests, demos and development tooling. Test i18n and placement algorithms at their ranuts owner; keep ranui facade checks.

## Experimental workspace retirement

- Remove the standalone `visual` workspace: its working geometry, transforms and events duplicate the maintained `ranuts/visual` engine, while GPU backends and chart components remain incomplete. Retain Shader learning notes, four GLSL examples and 69 referenced illustrations under `docs/learning/visual/`; drop the unreferenced image.
- Remove `ranite`: its CLI reaches only the simple Hello-world server, while the separate plugin/HMR server is not wired into the entry point and still has type/runtime defects. Existing Vite scripts remain the development path.
- Remove both package importers and prune their exclusive dependency graph. Update package listings, cleanup configuration and alpha migration guidance. These removals are intentional breaking changes; the old standalone visual exports are not a drop-in alias of `ranuts/visual`.

## Tooling and type contracts

- Limit `pnpm clean` to explicit repository-generated artifacts. Preserve dependencies, lockfiles and source/build configuration; skip symlink paths and reject invalid manifest directory names. Add isolated script regression checks to CI.
- Infer `requestUrlToBuffer` data from the requested XHR mode, defaulting to ArrayBuffer; JSON/dynamic responses require narrowing. Allow omitted options, type download progress callbacks and accept string inputs in createObjectURL.
- Normalize ESM declarations once for all three libraries, including NodeNext specifiers. Keep build-only Vite/assets declarations out of public typings and remove Node-only timer types from browser contracts.
- Publish ranuts, ranui and ranview as ESM-only packages. Remove CommonJS/UMD builds, require conditions and duplicate `.d.cts` forwarding graphs. Keep ranui full/component IIFEs and replace ranuts UMD browser bundles with IIFEs. Verify actual packed artifacts, ESM helper/SSR round trips and classic-script browser loading. Use Terser for the full ranui IIFE because the esbuild output is syntactically invalid for its dependency graph.
- Remove fake npm manifests from the native cpro/image-process examples; keep their native sources and build files. Preserve the retired debug workspace's Koa/Nginx reference material as learning documentation, and prune its exclusive dependencies.
