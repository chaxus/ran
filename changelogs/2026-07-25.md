# Changelog — 2026-07-25

把 ranui 里那些与组件无关的通用能力聚合到 ranuts，顺带清掉 ranuts 内部的一处重复。
两个包各自的公开 API 路径都没变，ranui 消费者无需改动任何 import。

净删除约 540 行重复实现。

## packages/ranuts

### 新增：从 ranui 上移的通用能力

| 模块              | 内容                                                                            |
| ----------------- | ------------------------------------------------------------------------------- |
| `utils/event.ts`  | `EventManager` —— 以 AbortController 为底座的作用域事件注册表 + 事件委托        |
| `utils/tween.ts`  | 七组缓动曲线（`quad`/`cubic`/`quart`/`quint`/`sine`/`expo`/`circ`）             |
| `utils/canvas.ts` | Canvas 2D 几何：`roundRectByArc`/`fanShapedByArc`/`getLinearGradient` 等        |
| `utils/style.ts`  | `adoptStyles` / `adoptSheetText` —— Shadow DOM 样式注入（Constructable + 降级） |
| `utils/i18n.ts`   | `I18nCore` / `createI18n` / `useI18n`，并新增 **`ranuts/i18n`** 子路径入口      |

`EventManager` 填的是 ranuts 此前完全缺失的一层：`removeEventListener` 必须拿到与注册时
完全相同的函数引用和 options 才生效，中途包一层箭头函数就再也摘不掉，反复挂载卸载的组件
于是每个周期漏一个监听。AbortController 把这件事变成一次 `abort()`。

`ranuts/i18n` 单独开子路径而不是只挂在 `ranuts/utils` 下，是为了让「只要 i18n」的消费者
不必吃下整个 utils barrel —— 实测走 barrel 是 23 KB 共享 chunk，走专用入口是 5.4 KB。

### 补齐：现有模块的缺口

- `utils/img.ts` 新增 `getImage` / `cutRound` / `opacity` / `getMatrix`。
  **`blur()` 没有一起搬** —— 它的循环体是空的（只有一句 `// 处理`），是个假实现。
- `utils/script.ts` 新增 `loadScript`：单个脚本、支持内联正文、按内容 md5 去重。与既有的
  `scriptOnLoad`（批量 url，`.css` 走 link 标签）分工不同，两者并存。
- `utils/color.ts` 补齐 `rgbToHsv` / `hexToHsb` / `hexToHsv` / `hsbToHsl` / `hslToHsb` /
  `hslToHsv` / `hexToAlpha` / `rgbaString` / `rgbaToRgb` / `rgbaToHex`，以及
  `HEX_COLOR_REGEX` / `RGB_REGEX` / `RGBA_REGEX`。

### 修复

- **`hexToRgb` 不认三位简写**。`#abc` 之前直接解析失败；现在按 CSS 规则展开成 `#aabbcc`
  （而不是补零 —— 补零会让 `#fff` 变成深灰）。返回类型同时从没法用的
  `RegExpExecArray | null | Array<number>` 收窄成 `Array<number> | null`。
- **`hsbToRgb` / `hsvToRgb` 用 `Math.floor` 收尾**，系统性地把每个通道压低最多 1，导致
  `rgb → hsb → rgb` 往返不收敛（颜色选择器上反复拖动会持续掉色）。改成 `round`。
  同一颜色的输出可能相差 1/255。
- **`loadScript` 的内联分支等一个永远不来的事件**。内联 script 在 append 的那一刻同步求值，
  之后不再派发 `load`，所以只等 `onload` 的 Promise 在真实浏览器里永远不 settle
  （jsdom 会派发，所以单测看不出来）。现在 `type: 'content'` 时 append 返回即视为完成。

### 内部去重

- `src/vnode/chainDom.ts` 是 `Chain` 的第二份副本，缺 SVG 命名空间支持和事件监听管理。
  已删除；`Chain` 拆到 `utils/chain.ts`，`ranuts/utils` 和 `ranuts/vnode` 共用能力更全的
  那一份（向后兼容的超集）。拆成独立文件是为了让 vnode 入口不必因此牵入 `utils/dom.ts`
  的其余部分（`setFontSize2html` 会连带引入 `utils/device`）。

### 根 barrel 不再手抄

`index.ts` 此前手工维护自己的一份导出名单，已经落后 **83 个符号** —— `EventManager`、
`createStore`、`resolveLocale`、`crc32`、整个 i18n 与 zip 接口，全都能从 `ranuts/utils`
拿到但从 `ranuts` 拿不到。现在改成 `export * from './src/utils'`：一份需要为每个新导出
编辑两次的名单，下个月必然又是错的。

### 文档

新增 `ranuts/i18n`、`event_manager`、`tween`、`canvas`、`adopt_styles`、`load_script`、
`image_process` 七个页面（中英各一份），`color.md` 补全新增函数，侧边栏新增
「Canvas 与动画」和「i18n」两个分组。`docs/API.md` 重新生成（332 exports / 5 entry points）。

## packages/ranui

### 删除与 ranuts 重复的实现

`utils/color.ts`(148 行)、`utils/tween.ts`(98)、`utils/math.ts`(220)、`utils/image.ts`(134)
整份删除；`utils/i18n/` 的引擎实现（182 行）下沉到 ranuts；`utils/style.ts` 从 92 行缩成
34 行（只保留把 ranui 自己的 `data-ranui` / `data-ranui-sheet` 标记绑到 ranuts 实现上 ——
标记属性是 ranui 渲染出的 DOM 的一部分，属于对外契约，不该跟着通用实现一起下沉）；
`utils/dom.ts` 的 `escapeHtml`、`loadScript`、14 项硬编码 MIME 表和
`utils/builder/escape.ts` 里的第二份 `escapeHtml` 全部改引 ranuts。

**所有对外 API 路径不变**：`@/utils/i18n`、`ranui/i18n`、`ranui` barrel、`loadScript`、
`adoptStyles` 全都照旧可用。

### 行为变化（需要注意）

- **单引号转义从 `&#039;` 变成 `&#39;`**。两者是同一字符的等价实体，渲染结果一致，但 SSR
  序列化出来的 HTML 字节会变 —— 比对快照或 golden file 时会看到差异。
- **`detectNavigator` 现在读完整的 `navigator.languages`**（此前只读 `navigator.language`）。
  首选语言在词典里没有的读者，现在能拿到他的第二选择，而不是直接掉到 fallback。
- **colorpicker 的颜色可能相差 1/255**，来自上面 `hsbToRgb` 的 floor → round 修复。

### 其它

- `utils/theme.ts` 改用 ranuts 的 `watchMediaQuery`，消掉了两个模块级可变状态
  （`_systemMediaQuery` / `_systemListener` 的手工解绑）；`theme.ts` 与 `utils/i18n` 各自
  手写的 localStorage try/catch 换成 ranuts 的守卫版本。
- colorpicker 的 6 处调用点从对象形（`{ r, g, b }`）改到 ranuts 的数组形（`[r, g, b]`）。
- `test/unit/colorpicker.color.utils.test.ts`、`utils.math.test.ts`、`utils.tween.test.ts`
  随实现一起迁到 ranuts（`test/color.test.ts` / `canvas.test.ts` / `tween.test.ts`，
  共 100 个用例）。需要 DOM 的图像用例留在 ranui —— ranuts 的测试环境是 node，没有 jsdom。

### e2e 基建：把隐式依赖变显式

两处「换台机器就全红、但看起来像测试挂了」的问题：

- **Playwright 浏览器不在依赖里**。`@playwright/test` 只是个库，浏览器二进制装在
  `~/Library/Caches/ms-playwright`，`pnpm install` 不会去装。新 clone 跑 e2e 会 207 个
  用例全部报 `browserType.launch: Executable doesn't exist`。现在 `test:e2e` / `test:ui` /
  `test:update` 会先跑新增的 `e2e:install`（已装则秒退，不联网）。
  `Google Chrome` 那个 project 用的是系统 Chrome（`channel: 'chrome'`），不在自动供给范围，
  文档里已注明。
- **dev server 端口从 5173 挪到 5273**。5173 是 Vite 默认端口，Playwright 的
  `reuseExistingServer` 会把任何在该端口应答的东西当成自己的 dev server —— 只要本机还开着
  另一个 Vite 项目，整个 e2e 套件就静默地在测别人的 app，症状是 200 个用例报页面标题不符。

### e2e 视觉测试：从 19 个 flake 到 3 连绿

跑通之后暴露出来的问题，逐个查清了根因：

- **动画根本没被冻住**。`isolatedSetup` 用 `page.addStyleTag()` 注入冻结 CSS，Playwright 自己的
  `animations: 'disabled'` 走 `document.getAnimations()` —— 组件全在 **closed shadow root** 里，
  这两条路都到不了边界内侧，而且都不会报错，动画照转，`toHaveScreenshot` 于是在每个 spinner 上
  死于 "Failed to take two consecutive stable screenshots"。改用
  `contextOptions: { reducedMotion: 'reduce' }`，触发 ranui 自己注入到每个 shadow root 里的
  `REDUCED_MOTION_CSS`。（`@playwright/test` 1.61 没有顶层 `use.reducedMotion`，只能走
  `contextOptions`，写错了 tsc 会报 TS2769。）
- **两个 spec 从来就没真正断言过任何东西**。`select — with value` 和 `modal — title visible`
  都通过 `host.shadowRoot` 取内部元素 —— closed root 下它恒为 `null`，断言静默退化成
  「元素找不到」。改用组件暴露的 `_shadowDom`。`modal` 还额外断言了
  `expect(page.locator('r-modal')).toBeVisible()`，而 `:host` 是 `position: static` 无尺寸、
  内容是 shadow root 里的 `position: fixed`，宿主盒子恒为 0×0，这条断言不可能通过。
- **字体未就位时量出的布局不确定**。`r-tab` 的滑动指示线自己量标签宽度并缓存，字体缓存冷热不同
  会差几个像素。`isolatedSetup` 现在先 `await document.fonts.ready`。
- 新增 `settlePending(page, selector)` helper：`r-loading` / `r-icon` 的变体是动态 import 的，
  等 `_pending` 而不是等一个拍脑袋的 `waitForTimeout(50)`。

结果：**207/207，连跑三次稳定**（此前 19 failed）。

### e2e CI：把已有的 Argos 覆盖真正跑起来

两套截图机制此前的分工是错位的：

- `toHaveScreenshot` 的基线在 gitignore 的 `screenshots/` 里，CI checkout 没有。原本若在 CI 跑，
  第一次会因「基线不存在」失败、retry 捡到自己刚写的文件然后变绿 —— 一个不可能失败的闸门比没有
  闸门更糟，因为它看起来像个闸门。现在 `ignoreSnapshots: !!process.env.CI` 明确把它限定为本地工具。
- `argosScreenshot` 才是 CI 的闸门（Argos 托管基线，跨平台可比）。但 `visual-regression.yml`
  只跑 `test/e2e/visual/`，而 15 个 spec 里有 12 个在 visual/ 之外 —— **77 个 argosScreenshot
  调用从来没在 CI 里触发过**。workflow 改为跑完整套件（`--project=chromium`）。

以 `CI=1` + 删掉本地基线模拟验证过：69 passed。
