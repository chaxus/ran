# 可选工作流模式

这些做法**只在任务能从中受益时**才适用。普通的表单、搜索页或编辑器默认不需要队列、账号连接或版本历史。[DESIGN.md](./DESIGN.md) 负责外观；[INTERACTION.md](./INTERACTION.md) 负责通用行为。工程实现由宿主负责；[ranui 工程规范](https://github.com/chaxus/ran/blob/main/packages/ranui/docs/CODING.md)是可选的组件库适配。这些都是宿主应用自己的决定，不是额外的组件 API、存储保证或捆绑的服务。

每条规则都有 ID 和等级。**MUST** 违反即为缺陷，并注明验证方式；**SHOULD** 是默认做法，偏离时要说明这次的理由；**MAY** 可选。[规则索引](./RULES.md)列出了所有分级规则及其验证方式。

- **W-RECIPE-1 · SHOULD** 对每个选用的模式，先确认应用支持什么，再选控件。
- **W-RECIPE-2 · SHOULD** 任务、配置、所选数据源和修订版本的状态留在它们现有的归属处。视图读取这些状态并派发命令，而不是在每个面板里各复制一份服务客户端和请求标记。

## 1. 批量任务与队列

**适用场景：** 有任务在运行时，用户能从提前准备下一次导入、上传或导出中受益。**宿主契约：** 派发、准备、并发／抢占、取消确认、部分写入、防重复和持久化。

| 状态           | 主操作               | 需要落定的契约                                   |
| -------------- | -------------------- | ------------------------------------------------ |
| 就绪           | 上传文件／导出报告   | 范围、目标位置和防止重复提交                     |
| 运行中         | 取消（如果支持）     | 停下的是什么、留下的是什么，以及写入是否已经提交 |
| 运行中有新任务 | 加入队列（如果支持） | 当前任务继续运行；新输入保留（W-QUEUE-2）        |
| 队列已暂停     | 继续队列             | 编辑待处理项不会派发它，也不会恢复队列           |
| 失败           | 重试／恢复输入       | 使用 INTERACTION §5 中区分开的各种结果           |

- **W-QUEUE-1 · SHOULD** 为上方队列表中的每个状态落定契约。
- **W-QUEUE-2 · MUST** 新任务绝不悄悄替换或取消正在运行的任务。不支持队列时，保留新输入并说明限制。_Proof: unit_
- **W-QUEUE-3 · MUST** 在已暂停的队列中编辑待处理项，既不会派发它，也不会恢复队列。_Proof: unit_
- **W-QUEUE-4 · SHOULD** 用一行概括排队中的任务，例如「2 个排队中」或「已暂停 · 2 个排队中」。
- **W-QUEUE-5 · SHOULD** 不需要时折叠队列详情；展开为行，而不是嵌套卡片。
- **W-QUEUE-6 · MUST** 每一行都能辨认出对应的项，并且只提供受支持的操作：编辑、移除或立即运行。_Proof: browser_
- **W-QUEUE-7 · SHOULD** 明确「立即运行」是等待、抢占还是并发运行。
- **W-QUEUE-8 · SHOULD** 准备过程在行内体现，而不是加一个塞满禁用命令的大面板。
- **W-QUEUE-9 · MUST** 编辑队列项时保留当前草稿，取消编辑时恢复它。_Proof: unit_
- **W-QUEUE-10 · MUST** 重新连接后不自动派发排队中的任务，除非用户选择了这种策略。_Proof: unit_
- **W-QUEUE-11 · SHOULD** 移除一行、折叠队列或停止任务时，应用[通用的焦点和取消规则](./INTERACTION.md)。

## 2. 感知能力的设置与离线工作

**适用场景：** 任务提供不同的服务商、模式、设备或依赖网络的能力。**宿主契约：** 配置存储、真实的验证操作、可达性和本地运行时依赖。

- **W-SETTINGS-1 · MUST** 保存配置和检查可用性是两个独立的操作，各有各的结果，并且各自显示完成了什么。_Proof: unit, browser_
- **W-SETTINGS-2 · SHOULD** 控件根据能力和状态推导，而不是依赖单一的 `connected` 布尔值。

远程存储账号、数据库服务或本地转换器都可能已经配置好，但当前并不可用。

| 状态             | 用户理解到的                             |
| ---------------- | ---------------------------------------- |
| 未配置           | 缺少一个必需的选择或凭据                 |
| 已配置，未验证   | 设置已保存；可用性尚未确认               |
| 已验证           | 对这份配置的真实检查成功了；记录检查时间 |
| 需要授权／已过期 | 重新连接账号，不丢弃已保存的工作         |
| 服务不可达       | 已保存的配置不能证明当前可达             |
| 设备离线         | 网络操作不可用；可用的本地工作可以继续   |

- **W-SETTINGS-3 · SHOULD** 让用户能区分上方设置表中的每个状态。
- **W-SETTINGS-4 · MUST** 重新连接需要授权或授权已过期的账号时，保留已保存的工作。_Proof: unit_
- **W-SETTINGS-5 · MUST** 相关的端点、账号或凭据设置变化时，作废之前的验证结果。_Proof: unit_
- **W-SETTINGS-6 · SHOULD** 浏览器的 online／offline 事件只当作提示，不能证明某个具体端点可用。
- **W-SETTINGS-7 · SHOULD** 只显示所选路径需要的设置。本地转换路径可能需要缓存／下载／设备相关的控件；远程路径可能需要端点／账号相关的控件。
- **W-SETTINGS-8 · MUST** 隐藏无关字段**及其过期的状态信息**。 _Proof: browser_
- **W-SETTINGS-9 · SHOULD** 设置页的标题栏、字段组、账号行以及不可用／空状态，保持 [DESIGN 对齐契约](./DESIGN.md#alignment-is-structure-not-polish)中命名的内容对齐线和导航对齐线。
- **W-SETTINGS-10 · SHOULD** 标题／菜单命令按内容收紧；标题栏的剩余空间交给单独的轨道。
- **W-SETTINGS-11 · SHOULD** 宣称区域已对齐之前，把嵌套面板和控件的内边距一直算到可见标签。
- **W-SETTINGS-12 · MUST** 切换模式时保留其他模式的配置。_Proof: unit_
- **W-SETTINGS-13 · SHOULD** 回到另一种模式的路径要容易找到。
- **W-SETTINGS-14 · SHOULD** 在披露数据之前说明数据的去向。
- **W-SETTINGS-15 · MUST** 配置好的 API 端点不能当作已授权的账号来展示。_Proof: review_
- **W-SETTINGS-16 · MUST** 离线时，只要数据和实现可用，就保留已保存的内容和草稿。_Proof: unit, browser_
- **W-SETTINGS-17 · SHOULD** 离线时，只要数据和实现可用，预览、编辑和导出就保持可用。
- **W-SETTINGS-18 · SHOULD** 离线时，隐藏只能联网使用、又提供不了有用路径的发现或推广内容；已连接的现有对象保留，并显示易于理解的不可用状态。
- **W-SETTINGS-19 · SHOULD** 缓存了某个资源，不代表所有运行时依赖都已就绪。
- **W-SETTINGS-20 · SHOULD** 重新连接后，提供一个明确的继续点。

## 3. 账号连接与外部数据源

**适用场景：** 工作需要读写当前对象之外的数据，无论在本地还是远程。**宿主契约：** 授权范围、身份、访问检查、撤销、凭据、来源追溯和导入副本的保留。有端点地址不等于有账号访问权限。

展示层基础组件不提供 OAuth 部署、凭据保管库、连接器后端或存储保证。再精致的连接界面也替代不了宿主的授权契约。

- **W-ACCOUNT-1 · SHOULD** 区分账号授权、对所选数据源的访问，以及某个具体操作对它的使用。
- **W-ACCOUNT-2 · SHOULD** 只申请需要的权限。
- **W-ACCOUNT-3 · SHOULD** 在授权或披露数据之前，说明会读什么、写什么以及写到哪里。
- **W-ACCOUNT-4 · MUST** 从连接界面可以看到账号身份，并能重新连接和撤销／断开。_Proof: browser_
- **W-ACCOUNT-5 · MUST** 断开后停止后续访问。_Proof: unit_
- **W-ACCOUNT-6 · SHOULD** 单独说明断开后导入的副本会怎样处理。
- **W-ACCOUNT-7 · MUST** 凭据不出现在 URL、日志和预览中。_Proof: review_
- **W-ACCOUNT-8 · SHOULD** 显示所选数据源的来源和新鲜度，无论它是本地文件、数据库记录还是云端文档。
- **W-ACCOUNT-9 · MUST** 移除数据源只影响之后的工作，不影响历史证据。_Proof: unit_
- **W-ACCOUNT-10 · MUST** 权限错误、过期数据和离线缓存副本各有不同的状态。_Proof: unit_
- **W-ACCOUNT-11 · MUST** 导入的内容当作不可信数据，而不是执行命令的许可。_Proof: review_
- **W-ACCOUNT-12 · MUST** 写入及其目标位置在发生之前就要明确告知。_Proof: browser_
- **W-ACCOUNT-13 · SHOULD** 写入前的审核步骤与写入的影响相称。

## 4. 结果、预览与修订

**适用场景：** 导出结果、转换后的文档或草稿有自己的身份和目标位置，不只是一条临时状态消息。**宿主契约：** 结果／修订身份、源版本、目标范围、提交确认、冲突处理，以及任何可撤回的历史。

- **W-REVISION-1 · SHOULD** 实质性内容优先使用合适的预览器／编辑器。
- **W-REVISION-2 · MUST** 只有宿主支持时，才提供比较、应用或撤销。_Proof: review_
- **W-REVISION-3 · SHOULD** 概括结果，并在相关时标明它的修订版本、来源和目标位置。
- **W-REVISION-4 · SHOULD** 受支持的复制、导出、比较或应用操作放在对应结果旁边。
- **W-REVISION-5 · MUST** 预览和应用分开，修改之前写明目标和范围。_Proof: browser_
- **W-REVISION-6 · MUST** 源数据变化时，应用之前先比较／变基或重新生成；较新的编辑绝不会被悄悄覆盖。_Proof: unit_
- **W-REVISION-7 · SHOULD** 按照[交互规范](./INTERACTION.md)确认保存／应用状态和可恢复的输出。

## 应用一个模式

- **W-APPLY-1 · MUST** 只保留宿主能够兑现的状态和操作。_Proof: review_
- **W-APPLY-2 · SHOULD** 精致的界面替代不了缺失的服务契约；把这个前提说清楚。

关键的转换已经有带单元测试验证的 MUST 规则：暂停的工作保持暂停（W-QUEUE-3），配置变化会作废验证（W-SETTINGS-5），移除数据源只影响之后的工作（W-ACCOUNT-9），过期的修订不能覆盖新的编辑（W-REVISION-6）。相关时，这些测试也覆盖中断和离线的情况。
