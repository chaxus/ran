# 交互规范

本文负责**可观察的行为**，与界面所在的业务领域或视觉处理无关。[DESIGN.md](./DESIGN.md) 负责外观；实现由宿主负责。对 ranui 贡献者，[CODING.md](https://github.com/chaxus/ran/blob/main/packages/ranui/docs/CODING.md) 提供工程层面的适配。只有遇到相关的多步骤任务时，才使用 [WORKFLOW_PATTERNS.md](./WORKFLOW_PATTERNS.md)。这些通用规则并不意味着要搭建任何工作流基础设施。

每条规则都有 ID 和等级。**MUST** 违反即为缺陷，并注明验证方式；**SHOULD** 是默认做法，偏离时要说明这次的理由；**MAY** 可选。[规则索引](./RULES.md)列出了所有分级规则及其验证方式。

## 1. 输入、草稿和意图

- **X-INPUT-1 · MUST** 标签、前置条件和校验信息紧挨着它们影响的字段。_Proof: browser_
- **X-INPUT-2 · SHOULD** 区分「缺少值」和「服务不可用」；前置条件不明显时，说明为什么暂时不能提交。
- **X-INPUT-3 · SHOULD** 使用合适的原生输入语义和自动填充，保留平台的编辑习惯；在有帮助的地方提供键盘快捷键。

| 转换                    | 预期行为                                               |
| ----------------------- | ------------------------------------------------------ |
| 空 → 表单有效           | 启用相关的提交操作；上下文控件保持可用                 |
| 提交 → 运行中           | 只派发一次；显示忙碌状态，不意外移动焦点               |
| 运行中 → 新的编辑       | 说明编辑影响的是本次任务、之后的任务，还是保留的草稿   |
| 失败 → 恢复             | 恢复只回填字段，不提交                                 |
| 失败 → 重试             | 重试会再次派发；保持原有范围，或在上下文变化时询问用户 |
| 设置／数据源变更 → 返回 | 尽可能保留未完成的输入和用户的选择                     |

- **X-INPUT-4 · MUST** 每次触发提交只派发一次；恢复只回填字段，不提交。_Proof: unit_
- **X-INPUT-5 · SHOULD** 遵循输入转换表中其余各行。
- **X-INPUT-6 · MUST** 只有字段的文档约定要求时，回车才提交；IME 组字期间绝不提交（检查 `isComposing`）。多行输入照常可用。_Proof: browser_
- **X-INPUT-7 · MUST** 语音输入只更新文字，绝不自行提交；开始语音输入之前已有的文字保留。_Proof: browser_
- **X-INPUT-8 · MUST** 不要因为搜索响应、流式更新、窗口缩放或状态变化而重建正在聚焦的输入框。_Proof: browser_
- **X-INPUT-9 · MUST** 以最新意图为准：旧查询的结果绝不替换新结果，一个文件的预览绝不出现在另一个文件下面。_Proof: unit_
- **X-INPUT-10 · SHOULD** 用宿主的异步身份标识和取消机制实现 X-INPUT-9；ranui 贡献者可以参考 [CODING §3](https://github.com/chaxus/ran/blob/main/packages/ranui/docs/CODING.md#3-state-and-ownership)。
- **X-INPUT-11 · MUST** 持久化成功之后才承诺已保存；保留的草稿不等于已保存的内容。_Proof: unit_
- **X-INPUT-12 · MUST** 高亮搜索匹配时使用安全的文本节点或等效转义，绝不把查询内容当作 HTML 插入。_Proof: unit_
- **X-INPUT-13 · SHOULD** 高亮匹配周围保留足够的文字，让人看出这一项为什么匹配。

## 2. 可触达的控件和可预期的焦点

- **X-FOCUS-1 · SHOULD** 用原生语义和受支持的组件契约构建控件。
- **X-FOCUS-2 · MUST** 每个纯图标操作都有无障碍名称。_Proof: browser_
- **X-FOCUS-3 · MUST** 悬停时显示的次要操作，在键盘聚焦时也要显示，并且在粗指针输入下有常驻的轻触入口。_Proof: browser_
- **X-FOCUS-4 · SHOULD** 关键的恢复操作保持可见，而不是悬停才出现。
- **X-FOCUS-5 · MUST** 禁用的控件悬停时没有反应，也无法派发操作。_Proof: browser_
- **X-FOCUS-6 · MUST** 标签或状态变化时，目标盒和聚焦环保持尺寸和位置不变。_Proof: browser_
- **X-FOCUS-7 · MUST** 通过公开的 attribute、事件、插槽、CSS 变量和 part 集成；不要修改私有的 shadow root。_Proof: review_
- **X-FOCUS-8 · MUST** 不要在宿主元素上添加无处可去、或与内部控件重复的 Tab 停留点。_Proof: browser_
- **X-FOCUS-9 · MUST** 组合出来的对话框打开时把初始焦点放在自身内部，Tab 和 Shift+Tab 在其中循环，按 Escape 和「取消」关闭，回车触发默认操作，关闭后焦点回到打开它的元素。_Proof: browser_
- **X-FOCUS-10 · SHOULD** 焦点陷阱够不到某个控件时（例如页脚里位于 closed shadow 中的按钮），修正受支持的集成方式，或把原生按钮放进它支持的插槽。
- **X-FOCUS-11 · MUST** 折叠的区域仍然标明其内容和状态；展开收起绝不能藏起尚未解决、需要处理的错误。_Proof: browser_
- **X-FOCUS-12 · MUST** 折叠包含焦点的区域时，焦点回到它的切换按钮；移除聚焦中的对象时，焦点移到下一个有意义的操作或稳定的父级控件。_Proof: browser_
- **X-FOCUS-13 · MUST** 不要仅仅因为后台请求完成就移动焦点。_Proof: browser_
- **X-FOCUS-14 · SHOULD** 折叠状态的摘要要帮读者判断是否展开；展开后的正文已经显示这些内容时，省去重复的摘要，保留标题和状态。

键盘安全的基础组件并不能让组合出来的对话框自动变得安全；X-FOCUS-9 针对的是组合本身。

## 3. 反馈和阅读位置

- **X-FEEDBACK-1 · SHOULD** 反馈显示在被操作的对象旁边。「复制」旁边出现「已复制」，比一条无关的全局通知更容易对应上；toast 适合当前对象之外的变化，或者不用 toast 就会被忽略的反馈。
- **X-FEEDBACK-2 · MUST** 操作成功之后才显示成功提示（对复制来说，是剪贴板写入成功之后），失败在本地处理，同时保持按钮的几何尺寸和焦点。_Proof: browser_
- **X-FEEDBACK-3 · MUST** 异步反馈属于操作发起时的源快照：复制尚未完成时内容发生了变化，旧的完成结果绝不能把新内容标成「已复制」；过期的反馈要清除或标明已过期。_Proof: unit, browser_
- **X-FEEDBACK-4 · MUST** 不要把每个流式输出的字符都播报给辅助技术。_Proof: browser_
- **X-FEEDBACK-5 · MUST** 实时日志和流式结果只在读者位于最新内容时自动跟随；滚动离开就暂停跟随，「跳到最新」恢复跟随，且不抢走阅读位置。_Proof: recording_
- **X-FEEDBACK-6 · SHOULD** 使用宿主或所选组件提供的、受支持的跟随／固定契约，任务和持久化状态留在应用中；只追加的阅读日志不是任务管理器。

对于 X-FEEDBACK-3，要测试中间夹着一次流式更新的延迟成功和延迟失败，而不只是孤立的延迟。

## 4. 进度、失败和恢复

- **X-RECOVER-1 · SHOULD** 已知阶段要写出名称（「正在读取文件」「正在检查权限」「正在写入导出文件」），而不只显示一个转圈；播报有意义的阶段变化，而不是每一次计时器跳动。
- **X-RECOVER-2 · MUST** 只有存在可测量的分母时才显示百分比；已用时间是次要信息，绝不当作完成时间的预估来展示。_Proof: review_
- **X-RECOVER-3 · MUST** 错误信息回答三件事：什么失败了、有没有东西已经改变、下一步怎么做；只承诺宿主能够确认的事情。_Proof: review_
- **X-RECOVER-4 · MUST** 存储失败时保留内存中的输入，并单独报告持久化失败。_Proof: unit_
- **X-RECOVER-5 · SHOULD** 不含凭据的诊断信息放在可选的详情里。
- **X-RECOVER-6 · SHOULD** 一次失败对应一个连贯的恢复方式，而不是重复的行和 toast。
- **X-RECOVER-7 · MUST** 超时不能证明已经回滚：重试会修改数据的操作之前，先确认它是否已经提交；宿主提供幂等或去重契约时就用上。_Proof: unit_

例如：「导入在保存前中断了。你选的文件还在。请重试导入。」

| 情况               | 有用的响应                                 | 避免                               |
| ------------------ | ------------------------------------------ | ---------------------------------- |
| 没有可读的文件内容 | 选择另一个文件；支持的话，也可以不带它继续 | 把每个操作都当成需要文档文本       |
| 网络中断           | 保留输入和部分输出；网络恢复后重试         | 清空表单，或宣布整个应用不可用     |
| 权限或配置被拒绝   | 说明属于哪一类问题；链接到相关的账号／设置 | 对缺少的授权或无效配置自动循环重试 |
| 用户取消           | 标记为已取消；保留可恢复的输出             | 用红色失败样式，或重启已暂停的工作 |
| 上下文已变化       | 标出过期的输出；基于当前数据刷新           | 悄悄把旧结果套用到更新后的文档上   |

## 5. 取消、重试和完成是不同的结果

- **X-CANCEL-1 · MUST** 同时支持「取消」和「提交」时，两者各自可达，无障碍名称清晰，位置稳定。_Proof: browser_
- **X-CANCEL-2 · MUST** 发出取消请求不等于取消已被确认：在确认之前显示等待状态；如果客户端只能停止等待，就如实说明，而不是声称任务已经停止。_Proof: unit_
- **X-CANCEL-3 · MUST** 取消不显示为失败。_Proof: browser_
- **X-CANCEL-4 · MUST** 重试会重新派发工作，但不悄悄扩大范围或更换目标；恢复只回填可编辑的输入。_Proof: unit_
- **X-CANCEL-5 · MUST** 写入确认之后才报告保存或应用成功，并保留可恢复的部分输出。_Proof: unit_
- **X-CANCEL-6 · MUST** 只有宿主确实能撤回操作时才提供「撤销」，并且绝不承诺「取消」能撤回已完成的写入。_Proof: review_

## 6. 验证人能观察到的东西

- **X-VERIFY-1 · SHOULD** 按缺陷选择证据，参照下面的分层，而不是为一个小改动跑遍所有可能的测试。
- **X-VERIFY-2 · SHOULD** 任务依赖外部工作时，把离线和失败路径也包括进来。
- **X-VERIFY-3 · SHOULD** 报告测试所用的提交，以及仍未满足的外部前提。

| 证据层     | 相关的回归                                                         |
| ---------- | ------------------------------------------------------------------ |
| 单元／状态 | 取消、迟到的响应、范围身份，以及重试与恢复的区别                   |
| 集成       | 草稿在上下文往返后保留；失败只有一处连贯的提示；浮层的键盘路径     |
| 真实浏览器 | 计算后的尺寸／基线／溢出、目标盒、焦点、禁用态悬停和 IME           |
| 跨界面     | 受影响的表单、搜索、历史、设置、导入／导出、预览和确认             |
| 变体       | 相关的主题、宽度、窗口缩放、键盘／粗指针输入、译文／RTL 和减弱动效 |

静态审查证明不了焦点恢复、最终生效的层叠样式或阅读位置是否保留。组件库贡献者使用 [CODING 的检查清单](https://github.com/chaxus/ran/blob/main/packages/ranui/docs/CODING.md#checklist-before-opening-a-pull-request)；使用方应用运行宿主自己的相关命令，而不是 ranui 源码仓库里的命令。
