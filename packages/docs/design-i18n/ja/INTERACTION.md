# 操作の基準

このファイルは、画面の領域や視覚的な扱いに左右されない**観察できる振る舞い**を持ちます。見た目は [DESIGN.md](./DESIGN.md) が持ち、実装はホストが持ちます。ranui のコントリビューターには、[CODING.md](https://github.com/chaxus/ran/blob/main/packages/ranui/docs/CODING.md) がエンジニアリングのアダプターを提供します。[WORKFLOW_PATTERNS.md](./WORKFLOW_PATTERNS.md) は、関係する複数ステップのタスクにだけ使ってください。ここにある一般的なルールは、ワークフローの基盤を何も前提としていません。

各ルールには ID と等級が付いています。**MUST** は破れば欠陥であり、その証拠の種類を明記します。**SHOULD** は既定であり、外れるときはその場合の理由を述べます。**MAY** は任意です。[ルール索引](./RULES.md)に、等級付きのすべてのルールとその証拠をまとめています。

## 1. 入力、下書き、意図

- **X-INPUT-1 · MUST** ラベル、前提条件、検証メッセージは、それが影響するフィールドの近くに置きます。_Proof: browser_
- **X-INPUT-2 · SHOULD** 値が欠けていることと、サービスが使えないことを区別し、前提条件が明らかでないときは、なぜ送信できないのかを説明します。
- **X-INPUT-3 · SHOULD** 適切なネイティブの入力の意味づけと autocomplete を使い、プラットフォームの編集の慣習を保ちます。役に立つ場面ではキーボードショートカットを提供します。

| 遷移                      | 期待される振る舞い                                                       |
| ------------------------- | ------------------------------------------------------------------------ |
| 空 → 有効なフォーム       | 関係する送信アクションを有効にし、文脈のコントロールは使えるままにする   |
| 送信 → 実行中             | 一度だけ送り出す。思いがけずフォーカスを動かさずに処理中の状態を示す     |
| 実行中 → 新しい編集       | 編集がこのジョブ、後のジョブ、残しておく下書きのどれに効くのかを明示する |
| 失敗 → 復元               | 復元はフィールドに値を戻すだけで、送信はしない                           |
| 失敗 → 再試行             | 再試行はもう一度送り出す。元の範囲を保つか、変わった文脈について尋ねる   |
| 設定／ソースの変更 → 戻る | 可能な限り、未完の入力とユーザーの選択を保つ                             |

- **X-INPUT-4 · MUST** 送信は起動ごとに一度だけ送り出し、復元はフィールドに値を戻すだけで送信はしません。_Proof: unit_
- **X-INPUT-5 · SHOULD** 入力の遷移表の残りの行に従います。
- **X-INPUT-6 · MUST** Enter で送信するのは、そのフィールドの文書化された慣習がそう求める場合だけで、IME の変換中には決して送信しません（`isComposing` を確かめます）。複数行の入力は動き続けます。_Proof: browser_
- **X-INPUT-7 · MUST** 音声入力はテキストを更新するだけで、それ自体が送信することはありません。取り込みの前にあったテキストは保たれます。_Proof: browser_
- **X-INPUT-8 · MUST** 検索の応答、ストリームの更新、リサイズ、ステータスの変化で、フォーカスのある入力欄を作り直さないでください。_Proof: browser_
- **X-INPUT-9 · MUST** 最新の意図が勝ちます：古い問い合わせが新しい結果を置き換えることはなく、あるファイルのプレビューが別のファイルの下に表示されることもありません。_Proof: unit_
- **X-INPUT-10 · SHOULD** X-INPUT-9 は、ホストの非同期の識別とキャンセルの仕組みで実装します。ranui のコントリビューターは [CODING §3](https://github.com/chaxus/ran/blob/main/packages/ranui/docs/CODING.md#3-state-and-ownership) を参照できます。
- **X-INPUT-11 · MUST** 保存を約束するのは、それが成功してからです。残しておいた下書きは、保存したものではありません。_Proof: unit_
- **X-INPUT-12 · MUST** 検索の一致箇所の強調は、安全なテキストノードか同等のエスケープで行い、問い合わせを HTML として挿入することは決してしません。_Proof: unit_
- **X-INPUT-13 · SHOULD** 強調した一致箇所の周りに、その項目がなぜ一致したのかが分かるだけのテキストを残します。

## 2. たどり着けるコントロールと予測できるフォーカス

- **X-FOCUS-1 · SHOULD** コントロールは、ネイティブの意味づけとサポートされたコンポーネントの契約から組み立てます。
- **X-FOCUS-2 · MUST** アイコンだけのアクションには、すべてアクセシブルな名前があります。_Proof: browser_
- **X-FOCUS-3 · MUST** ホバーで現れる二次的なアクションは、キーボードフォーカスでも現れ、粗い入力では常にタップできる経路があります。_Proof: browser_
- **X-FOCUS-4 · SHOULD** 欠かせない復旧のアクションは、ホバーで現れるのではなく、見えたままにします。
- **X-FOCUS-5 · MUST** 無効なコントロールはホバーしても静かなままで、送り出すことができません。_Proof: browser_
- **X-FOCUS-6 · MUST** ラベルやステータスが変わるあいだも、ターゲットのボックスとフォーカスリングは大きさと位置を保ちます。_Proof: browser_
- **X-FOCUS-7 · MUST** 公開された属性、イベント、スロット、変数、パーツを通して組み込みます。非公開のシャドウルートに手を加えないでください。_Proof: review_
- **X-FOCUS-8 · MUST** どこにも行き着かない、または内側のコントロールと重複する、ホストのタブ移動先を足さないでください。_Proof: browser_
- **X-FOCUS-9 · MUST** 組み立てたダイアログは、最初のフォーカスを自身の内側に置き、Tab と Shift+Tab をその中に留め、Escape と Cancel で閉じ、Enter で既定のアクションを起動し、閉じたときにフォーカスを開いた要素に戻します。_Proof: browser_
- **X-FOCUS-10 · SHOULD** フォーカストラップがあるコントロールに届かない場合（たとえばフッターにある closed シャドウの中のボタン）は、サポートされた組み込み方を直すか、サポートされたスロットにネイティブのボタンを置きます。
- **X-FOCUS-11 · MUST** 折りたたんだ領域も、その中身と状態を示し続けます。開閉によって、未解決で対処の必要なエラーを隠すことはありません。_Proof: browser_
- **X-FOCUS-12 · MUST** フォーカスを含む領域を折りたたむと、フォーカスはその開閉ボタンに戻ります。フォーカスのある対象を取り除くと、フォーカスは次の意味のあるアクションか、安定した親のコントロールに移ります。_Proof: browser_
- **X-FOCUS-13 · MUST** バックグラウンドのリクエストが完了したというだけで、フォーカスを動かさないでください。_Proof: browser_
- **X-FOCUS-14 · SHOULD** 折りたたんだときの概要は、読み手が展開するかどうかを決める助けになるように書きます。展開した本文がすでにその内容を見せているなら、繰り返しの概要は省き、タイトルと状態を残します。

キーボードで安全なプリミティブを使っても、組み立てたダイアログが安全になるわけではありません。X-FOCUS-9 が扱うのは組み立てです。

## 3. フィードバックと読んでいる位置

- **X-FEEDBACK-1 · SHOULD** フィードバックは、操作した対象の隣に表示します。コピーボタンの横の「コピーしました」は、無関係な全体の通知より結び付けやすいものです。トーストは、現在の対象を越える変化や、ほかの方法では気づかれないフィードバックに向いています。
- **X-FEEDBACK-2 · MUST** 成功の通知は、操作が成功してから表示し（コピーなら、クリップボードへの書き込みが成功してから）、拒否された場合はボタンの形とフォーカスを保ったままその場で扱います。_Proof: browser_
- **X-FEEDBACK-3 · MUST** 非同期のフィードバックは、操作を始めた時点のソースのスナップショットに属します：コピーの処理中に内容が変わったとき、古い完了が新しい内容を「コピーしました」とすることはなく、古いフィードバックは消すか、古いものと分かるようにします。_Proof: unit, browser_
- **X-FEEDBACK-4 · MUST** ストリームで流れてくる 1 文字ごとに、支援技術へ読み上げを通知しないでください。_Proof: browser_
- **X-FEEDBACK-5 · MUST** ライブのログやストリームの結果は、読み手が最新の内容にいるあいだだけ追従します。スクロールで離れると追従を止め、「最新へ移動」で読んでいる位置を奪わずに追従を再開します。_Proof: recording_
- **X-FEEDBACK-6 · SHOULD** ホストまたは選んだコンポーネントの、サポートされた追従／固定の契約を使い、ジョブと保存の状態はアプリケーションに持たせます。追記していくだけの読み取り用ログは、ジョブの管理役ではありません。

X-FEEDBACK-3 については、単独の遅延だけでなく、途中にストリームの更新を挟んだ遅れた成功と失敗を試してください。

## 4. 進捗、失敗、復旧

- **X-RECOVER-1 · SHOULD** スピナーだけを見せるのではなく、分かっている段階（「ファイルを読み込み中」「権限を確認中」「書き出しを保存中」）を名指しし、タイマーの刻みごとではなく意味のある段階の変化を通知します。
- **X-RECOVER-2 · MUST** パーセントを表示するのは、測れる分母があるときだけです。経過時間は二次的な情報で、完了の見込みとして示すことはありません。_Proof: review_
- **X-RECOVER-3 · MUST** エラーは、何が失敗したか、何か変わったか、次に何をすべきかに答え、ホストが確かめられることだけを約束します。_Proof: review_
- **X-RECOVER-4 · MUST** ストレージへの保存が失敗してもメモリ上の入力は保ち、保存の失敗は別に知らせます。_Proof: unit_
- **X-RECOVER-5 · SHOULD** 認証情報を含まない診断情報は、任意で開ける詳細に置きます。
- **X-RECOVER-6 · SHOULD** ひとつの失敗には、重複した行やトーストではなく、ひとつのまとまった復旧を与えます。
- **X-RECOVER-7 · MUST** タイムアウトはロールバックの証明になりません：変更を伴う操作を再試行する前に、それが確定したかどうかを、可能ならホストの冪等性や重複排除の契約を使って確かめます。_Proof: unit_

たとえば：「インポートは保存の前に止まりました。選んだファイルはそのまま残っています。インポートを再試行してください。」

| 状況                       | 役に立つ応答                                         | 避けること                                               |
| -------------------------- | ---------------------------------------------------- | -------------------------------------------------------- |
| 読めるファイルの内容がない | 別のファイルを選ぶか、対応していればそれなしで続ける | すべてのアクションに文書のテキストが必要だとみなす       |
| ネットワークが途切れた     | 入力や途中までの出力を保ち、つながったら再試行する   | フォームを消す、アプリケーション全体を使えないと宣言する |
| 権限や設定が拒否された     | 種類を説明し、関係するアカウント／設定へリンクする   | 権限の不足や無効な設定に対する自動の再試行ループ         |
| ユーザーがキャンセルした   | キャンセル済みと示し、取り戻せる出力を残す           | 赤い失敗のスタイル、一時停止した作業の再開               |
| 文脈が変わった             | 古くなった出力を示し、現在のデータに対して更新する   | 古い結果を新しい文書に黙って適用する                     |

## 5. キャンセル、再試行、完了は別々の結果

- **X-CANCEL-1 · MUST** キャンセルと送信の両方に対応しているなら、それぞれ独立してたどり着けるようにし、はっきりしたアクセシブルな名前と安定した位置を与えます。_Proof: browser_
- **X-CANCEL-2 · MUST** キャンセルの要求は、受け付けられたキャンセルではありません：確認されるまでは保留中の状態を示し、クライアントが待つのをやめることしかできないなら、ジョブが止まったと主張するのではなく、そう伝えます。_Proof: unit_
- **X-CANCEL-3 · MUST** キャンセルを失敗として表示しません。_Proof: browser_
- **X-CANCEL-4 · MUST** 再試行は、黙って範囲を広げたり行き先を切り替えたりせずに、作業をもう一度送り出します。復元は編集できる入力に値を戻すだけです。_Proof: unit_
- **X-CANCEL-5 · MUST** 保存や適用の成功を伝えるのは書き込みが確認されてからにし、取り戻せる途中までの出力は残します。_Proof: unit_
- **X-CANCEL-6 · MUST** 元に戻すを提供するのは、ホストが実際にその操作を取り消せるときだけにし、キャンセルが完了済みの書き込みを取り消すとは決して約束しません。_Proof: review_

## 6. 人が観察できることを検証する

- **X-VERIFY-1 · SHOULD** 小さな変更のために考えうるすべてのテストを実行するのではなく、欠陥に応じて、下の層から証拠を選びます。
- **X-VERIFY-2 · SHOULD** タスクが外部の作業に依存するなら、オフラインと失敗の経路も含めます。
- **X-VERIFY-3 · SHOULD** テストしたコミットと、残っている外部の前提条件を報告します。

| 証拠の層         | 関係する回帰                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------- |
| ユニット／状態   | キャンセル、遅れた応答、範囲の識別、再試行と復元の違い                                        |
| 結合             | 下書きが文脈の往復を越えて残る、ひとつのまとまった失敗、オーバーレイのキーボード経路          |
| 実際のブラウザー | 計算された寸法／ベースライン／はみ出し、ターゲットのボックス、フォーカス、無効時のホバー、IME |
| 面をまたぐ       | 影響を受けるフォーム、検索、履歴、設定、インポート／エクスポート、プレビュー、確認            |
| バリエーション   | 関係するテーマ、幅、リサイズ、キーボード／粗い入力、翻訳／RTL、モーション軽減                 |

静的な監査では、フォーカスの復帰、勝ち残ったカスケード、保たれた読んでいる位置は証明できません。ライブラリのコントリビューターは [CODING のチェックリスト](https://github.com/chaxus/ran/blob/main/packages/ranui/docs/CODING.md#checklist-before-opening-a-pull-request)を使います。利用側のアプリケーションは、ranui のソースをチェックアウトして使うコマンドではなく、ホストの関係するコマンドを使います。
