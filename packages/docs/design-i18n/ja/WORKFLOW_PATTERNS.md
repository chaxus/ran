# 任意のワークフローパターン

これらのレシピは、**タスクにとって役に立つときだけ**当てはめます。普通のフォーム、検索ページ、エディターは、既定ではキュー、アカウント連携、バージョン履歴を必要としません。見た目は [DESIGN.md](./DESIGN.md) が、一般的な振る舞いは [INTERACTION.md](./INTERACTION.md) が持ちます。エンジニアリングはホストが持ち、[ranui のエンジニアリング](https://github.com/chaxus/ran/blob/main/packages/ranui/docs/CODING.md)は任意のライブラリアダプターです。これらはホストアプリケーションの判断であって、追加のコンポーネント API、ストレージの保証、同梱のサービスではありません。

各ルールには ID と等級が付いています。**MUST** は破れば欠陥であり、その証拠の種類を明記します。**SHOULD** は既定であり、外れるときはその場合の理由を述べます。**MAY** は任意です。[ルール索引](./RULES.md)に、等級付きのすべてのルールとその証拠をまとめています。

- **W-RECIPE-1 · SHOULD** 選んだレシピごとに、コントロールを選ぶ前に、アプリケーションが何に対応しているかを確かめます。
- **W-RECIPE-2 · SHOULD** ジョブ、設定、選んだソース、リビジョンの状態は、既存の持ち主に持たせます。ビューはその状態を読んでコマンドを送り出し、パネルごとにサービスのクライアントやリクエストのフラグを複製しません。

## 1. まとめての作業とキュー

**使う場面：** 作業の実行中に、別のインポート、アップロード、エクスポートを準備できると役に立つとき。
**ホストの契約：** 送り出し、準備、並行実行／割り込み、キャンセルの受け付け、途中までの書き込み、重複の防止、保存。

| 状態                     | 主なアクション                                 | 決めておく契約                                                   |
| ------------------------ | ---------------------------------------------- | ---------------------------------------------------------------- |
| 準備完了                 | ファイルをアップロード／レポートをエクスポート | 範囲、行き先、二重送信の防止                                     |
| 実行中                   | キャンセル（対応していれば）                   | 何が止まり、何が残り、書き込みが確定したかどうか                 |
| 実行中に新しい作業がある | キューに追加（対応していれば）                 | 実行中のジョブは動き続け、新しい入力は保たれる（W-QUEUE-2）      |
| キューが一時停止中       | キューを再開                                   | 保留中の項目を編集しても、それが送り出されたり再開したりはしない |
| 失敗                     | 再試行／入力を復元                             | INTERACTION §5 の別々の結果を使う                                |

- **W-QUEUE-1 · SHOULD** 上のキューの表の状態ごとに契約を決めます。
- **W-QUEUE-2 · MUST** 新しい作業が、実行中のジョブを黙って置き換えたりキャンセルしたりすることは決してありません。キューに対応していないなら、新しい入力を保ち、その制約を説明します。_Proof: unit_
- **W-QUEUE-3 · MUST** 一時停止中のキューで保留中の項目を編集しても、その項目を送り出すことも、キューを再開することもありません。_Proof: unit_
- **W-QUEUE-4 · SHOULD** キューに入った作業は「2 件待機中」や「一時停止中 · 2 件待機中」のように 1 行で要約します。
- **W-QUEUE-5 · SHOULD** キューの詳細は必要ないときには折りたたみ、入れ子のカードではなく行として展開します。
- **W-QUEUE-6 · MUST** どの行にも識別できる項目があり、提供するのはサポートされたアクション（編集、削除、今すぐ実行）だけです。_Proof: browser_
- **W-QUEUE-7 · SHOULD** 「今すぐ実行」が待つのか、割り込むのか、並行して実行するのかを決めます。
- **W-QUEUE-8 · SHOULD** 準備中であることは、無効なコマンドだらけの大きなパネルを足すのではなく、行の中で表します。
- **W-QUEUE-9 · MUST** キューの編集は現在の下書きを保ち、編集をキャンセルすると下書きが元に戻ります。_Proof: unit_
- **W-QUEUE-10 · MUST** ユーザーがその方針を選んでいない限り、再接続でキューの作業が自動的に送り出されることはありません。_Proof: unit_
- **W-QUEUE-11 · SHOULD** 行を削除する、キューを折りたたむ、作業を止めるときは、[一般的なフォーカスとキャンセルのルール](./INTERACTION.md)を当てはめます。

## 2. 能力に応じた設定とオフラインの作業

**使う場面：** タスクが、別々のプロバイダー、モード、デバイス、またはネットワークに依存する能力を提供するとき。
**ホストの契約：** 設定の保存、実際の検証操作、到達可能性、ローカルのランタイムの依存。

- **W-SETTINGS-1 · MUST** 設定の保存と利用可否の確認は、別々の結果を持つ別々のアクションで、それぞれが何を成し遂げたかを示します。_Proof: unit, browser_
- **W-SETTINGS-2 · SHOULD** コントロールは、`connected` というひとつの真偽値ではなく、能力と状態から導きます。

リモートのストレージアカウント、データベースのサービス、ローカルの変換ツールは、設定済みでも今は使えないことがあります。

| 状態                   | ユーザーが理解すること                                         |
| ---------------------- | -------------------------------------------------------------- |
| 未設定                 | 必要な選択や認証情報が欠けている                               |
| 設定済み・未検証       | 設定は保存されたが、利用できるかはまだ確かめられていない       |
| 検証済み               | この設定で実際の確認が成功した。いつ成功したかを記録する       |
| 認可が必要／期限切れ   | 保存した作業を捨てずにアカウントを再接続する                   |
| サービスに到達できない | 保存した設定は、今つながることの証明にならない                 |
| デバイスがオフライン   | ネットワークの操作は使えない。使えるローカルの作業は続けられる |

- **W-SETTINGS-3 · SHOULD** 上の設定の表の各状態を、ユーザーが区別できるようにします。
- **W-SETTINGS-4 · MUST** 認可が必要または期限切れのアカウントを再接続しても、保存した作業は保たれます。_Proof: unit_
- **W-SETTINGS-5 · MUST** 関係するエンドポイント、アカウント、認証情報の設定が変わったら、検証を無効にします。_Proof: unit_
- **W-SETTINGS-6 · SHOULD** ブラウザーの online／offline イベントは、特定のエンドポイントが動いている証明ではなく、手がかりとして扱います。
- **W-SETTINGS-7 · SHOULD** 選んだ経路の設定を表示します。ローカルの変換経路にはキャッシュ／ダウンロード／デバイスのコントロールが、リモートの経路にはエンドポイント／アカウントのコントロールが必要なことがあります。
- **W-SETTINGS-8 · MUST** 関係のないフィールド**とその古いステータスメッセージ**を隠します。_Proof: browser_
- **W-SETTINGS-9 · SHOULD** 設定のヘッダー、フィールドのグループ、アカウントの行、利用不可／空の状態は、[DESIGN の揃えの契約](./DESIGN.md#alignment-is-structure-not-polish)で名付けた内容とナビゲーションの背骨を保ちます。
- **W-SETTINGS-10 · SHOULD** タイトル／メニューのコマンドは内容に沿わせ、ヘッダーの埋め草は別のトラックに吸収させます。
- **W-SETTINGS-11 · SHOULD** 領域が揃っていると判断する前に、入れ子のパネルとコントロールの内側余白を、見えるラベルまで数えます。
- **W-SETTINGS-12 · MUST** モードを切り替えても、ほかのモードの設定は保たれます。_Proof: unit_
- **W-SETTINGS-13 · SHOULD** 別のモードへ戻る経路を見つけやすいままにします。
- **W-SETTINGS-14 · SHOULD** 開示の前に、データの行き先を説明します。
- **W-SETTINGS-15 · MUST** 設定済みの API エンドポイントを、認可されたアカウントとして示しません。_Proof: review_
- **W-SETTINGS-16 · MUST** オフラインでも、データと実装が使えるなら、保存した内容と下書きを保ちます。_Proof: unit, browser_
- **W-SETTINGS-17 · SHOULD** オフラインでも、データと実装が使えるなら、プレビュー、編集、エクスポートを使えるままにします。
- **W-SETTINGS-18 · SHOULD** オフラインでは、役に立つ経路のない、ネットワーク専用の発見や宣伝を隠します。既存の接続済みの対象は、理解できる利用不可の状態で残します。
- **W-SETTINGS-19 · SHOULD** キャッシュされたリソースがあっても、すべてのランタイムの依存がそろっている証明にはならないものとして扱います。
- **W-SETTINGS-20 · SHOULD** 再接続の後に、意図した続きの地点を提供します。

## 3. アカウント連携と外部のソース

**使う場面：** 作業が、ローカルかリモートかを問わず、現在の対象の外にあるデータを読み書きするとき。
**ホストの契約：** 認可のスコープ、アイデンティティ、アクセスの確認、取り消し、認証情報、出どころ、取り込んだコピーの保持。エンドポイントのアドレスは、アカウントへのアクセスを示しません。

表示用のプリミティブは、OAuth のデプロイ、認証情報の保管庫、コネクターのバックエンド、ストレージの保証を何も提供しません。整った接続画面でも、ホストの認可の契約の代わりにはなりません。

- **W-ACCOUNT-1 · SHOULD** アカウントの認可、選んだソースへのアクセス、特定の操作による利用を区別します。
- **W-ACCOUNT-2 · SHOULD** 必要な権限だけを求めます。
- **W-ACCOUNT-3 · SHOULD** 認可や開示の前に、読むもの、書くもの、行き先を説明します。
- **W-ACCOUNT-4 · MUST** アカウントのアイデンティティ、再接続、取り消し／切断には、接続の UI からたどり着けます。_Proof: browser_
- **W-ACCOUNT-5 · MUST** 切断すると、以後のアクセスは止まります。_Proof: unit_
- **W-ACCOUNT-6 · SHOULD** 切断したときに取り込んだコピーがどうなるかは、別に説明します。
- **W-ACCOUNT-7 · MUST** 認証情報を URL、ログ、プレビューに含めないでください。_Proof: review_
- **W-ACCOUNT-8 · SHOULD** 選んだソースについて、ローカルのファイル、データベースのレコード、クラウドの文書のいずれであっても、出どころと新しさを示します。
- **W-ACCOUNT-9 · MUST** ソースを取り除いて影響を受けるのはこれからの作業であって、過去の証拠ではありません。_Proof: unit_
- **W-ACCOUNT-10 · MUST** 権限のエラー、古いデータ、オフラインのキャッシュされたコピーは、それぞれ別の状態を持ちます。_Proof: unit_
- **W-ACCOUNT-11 · MUST** 取り込んだ内容は信頼できないデータとして扱い、コマンドを実行する許可としては扱いません。_Proof: review_
- **W-ACCOUNT-12 · MUST** 書き込みとその行き先は、それが起きる前に明示します。_Proof: browser_
- **W-ACCOUNT-13 · SHOULD** 書き込みの前のレビューの手順は、その影響の大きさに合わせます。

## 4. 結果、プレビュー、リビジョン

**使う場面：** エクスポート、変換した文書、下書きが、一時的なステータスメッセージを越えるアイデンティティと行き先を持つとき。
**ホストの契約：** 結果／リビジョンのアイデンティティ、ソースのバージョン、対象の範囲、確定の受け付け、競合の扱い、取り消せる履歴。

- **W-REVISION-1 · SHOULD** 中身のある内容には、適切なプレビュー／エディターを優先します。
- **W-REVISION-2 · MUST** 比較、適用、元に戻すを提供するのは、ホストがそれに対応しているときだけです。_Proof: review_
- **W-REVISION-3 · SHOULD** 結果を要約し、関係するときはそのリビジョン、ソース、行き先を示します。
- **W-REVISION-4 · SHOULD** サポートされたコピー、エクスポート、比較、適用のアクションは、関係する結果のそばに置きます。
- **W-REVISION-5 · MUST** プレビューと適用を分け、変更の前に対象と範囲を名指しします。_Proof: browser_
- **W-REVISION-6 · MUST** ソースのデータが変わっていたら、適用の前に比較／リベースするか生成し直します。新しい編集が黙って上書きされることは決してありません。_Proof: unit_
- **W-REVISION-7 · SHOULD** 保存済み／適用済みの状態と取り戻せる出力は、[操作の基準](./INTERACTION.md)に従って確認します。

## レシピを当てはめる

- **W-APPLY-1 · MUST** ホストが守れる状態とアクションだけを残します。_Proof: review_
- **W-APPLY-2 · SHOULD** 整った画面でも、欠けているサービスの契約の代わりにはなりません。その前提条件をはっきり述べます。

主要な遷移には、すでにユニットテストの証拠を伴う MUST のルールがあります：一時停止した作業は一時停止したまま（W-QUEUE-3）、変わった設定は検証を無効にする（W-SETTINGS-5）、ソースの削除はこれからの作業にだけ影響する（W-ACCOUNT-9）、古いリビジョンは新しい編集を上書きできない（W-REVISION-6）。これらのテストは、関係する場合に中断された作業とオフラインの作業も扱います。
