# 상호작용 표준

이 문서는 화면의 도메인이나 시각 처리와 상관없이 **관찰 가능한 동작**을 담당합니다.
겉모습은 [DESIGN.md](./DESIGN.md)가, 구현은 호스트가 담당합니다. ranui 기여자에게는
[CODING.md](https://github.com/chaxus/ran/blob/main/packages/ranui/docs/CODING.md)가 엔지니어링 어댑터 역할을 합니다.
[WORKFLOW_PATTERNS.md](./WORKFLOW_PATTERNS.md)는 해당하는 여러 단계짜리 작업에만 쓰세요.
이 일반 규칙들이 워크플로 인프라를 전제하지는 않습니다.

각 규칙에는 ID 와 등급이 붙습니다. **MUST**는 어기면 결함이며 증거 방식을 명시합니다.
**SHOULD**는 기본값이고, 벗어날 때는 그 경우의 이유를 밝힙니다. **MAY**는 선택입니다.
[규칙 색인](./RULES.md)에 등급이 붙은 모든 규칙과 증거 방식이 정리되어 있습니다.

## 1. 입력, 초안, 의도

- **X-INPUT-1 · MUST** 레이블, 전제 조건, 유효성 메시지는 그것이 영향을 주는 필드 가까이에 둡니다. _Proof: browser_
- **X-INPUT-2 · SHOULD** 값이 비어 있는 것과 서비스를 쓸 수 없는 것을 구분하고, 전제 조건이 분명하지 않을 때는 왜 제출할 수 없는지 설명하세요.
- **X-INPUT-3 · SHOULD** 알맞은 네이티브 입력 시맨틱과 자동 완성을 쓰고, 플랫폼의 편집 관례를 지키세요. 도움이 되는 곳에는 키보드 단축키를 제공하세요.

| 전환                      | 기대하는 동작                                                          |
| ------------------------- | ---------------------------------------------------------------------- |
| 빈 폼 → 유효한 폼         | 해당 제출 액션을 활성화하고, 맥락 컨트롤은 계속 쓸 수 있게 둠          |
| 제출 → 실행 중            | 한 번만 보냄. 처리 중 상태를 드러내되 포커스를 예기치 않게 옮기지 않음 |
| 실행 중 → 새 편집         | 편집이 이번 작업에 반영되는지, 다음 작업인지, 보존된 초안인지 정해 둠  |
| 실패 → 복원               | 복원은 필드만 다시 채움. 제출하지 않음                                 |
| 실패 → 재시도             | 재시도는 다시 보냄. 원래 범위를 유지하거나 바뀐 맥락에 대해 물어봄     |
| 설정/소스 변경 → 돌아오기 | 가능하면 끝나지 않은 입력과 사용자의 선택을 유지                       |

- **X-INPUT-4 · MUST** 제출은 활성화 한 번에 한 번만 보내고, 복원은 제출하지 않고 필드만 다시 채웁니다. _Proof: unit_
- **X-INPUT-5 · SHOULD** 입력 전환 표의 나머지 행을 따르세요.
- **X-INPUT-6 · MUST** Enter 는 필드의 문서화된 관례가 그렇게 정한 곳에서만 제출하고, IME 조합 중에는 절대 제출하지 않습니다 (`isComposing` 확인). 여러 줄 입력은 계속 동작합니다. _Proof: browser_
- **X-INPUT-7 · MUST** 받아쓰기는 텍스트를 갱신할 뿐 스스로 제출하지 않으며, 받아쓰기 전에 있던 텍스트는 유지됩니다. _Proof: browser_
- **X-INPUT-8 · MUST** 검색 응답, 스트림 갱신, 크기 변경, 상태 변화 때문에 포커스된 입력을 다시 만들지 않습니다. _Proof: browser_
- **X-INPUT-9 · MUST** 가장 최근 의도가 이깁니다. 오래된 쿼리가 더 새로운 결과를 덮어쓰지 않고, 한 파일의 미리보기가 다른 파일 아래에 나타나지 않습니다. _Proof: unit_
- **X-INPUT-10 · SHOULD** X-INPUT-9 는 호스트의 비동기 식별·취소 메커니즘으로 구현하세요. ranui 기여자는 [CODING §3](https://github.com/chaxus/ran/blob/main/packages/ranui/docs/CODING.md#3-state-and-ownership)을 참고할 수 있습니다.
- **X-INPUT-11 · MUST** 저장은 성공한 뒤에만 약속합니다. 보존된 초안은 저장된 것이 아닙니다. _Proof: unit_
- **X-INPUT-12 · MUST** 검색 일치 부분은 안전한 텍스트 노드나 그에 준하는 이스케이프로 강조하고, 쿼리를 HTML 로 삽입해서 강조하지 않습니다. _Proof: unit_
- **X-INPUT-13 · SHOULD** 강조된 일치 부분 주변에 그 항목이 왜 일치했는지 알 수 있을 만큼 텍스트를 남기세요.

## 2. 닿을 수 있는 컨트롤과 예측 가능한 포커스

- **X-FOCUS-1 · SHOULD** 컨트롤은 네이티브 시맨틱과 지원되는 컴포넌트 계약으로 만드세요.
- **X-FOCUS-2 · MUST** 아이콘만 있는 모든 액션에는 접근 가능한 이름이 있습니다. _Proof: browser_
- **X-FOCUS-3 · MUST** 호버로 드러나는 보조 액션은 키보드 포커스로도 드러나고, 거친 입력에서는 늘 탭할 수 있는 경로가 있습니다. _Proof: browser_
- **X-FOCUS-4 · SHOULD** 꼭 필요한 복구 액션은 호버로 드러내지 말고 늘 보이게 두세요.
- **X-FOCUS-5 · MUST** 비활성 컨트롤은 호버에 반응하지 않고 아무것도 보낼 수 없습니다. _Proof: browser_
- **X-FOCUS-6 · MUST** 레이블이나 상태가 바뀌는 동안에도 대상 상자와 포커스 링의 크기와 위치는 그대로입니다. _Proof: browser_
- **X-FOCUS-7 · MUST** 공개 어트리뷰트, 이벤트, 슬롯, 변수, part 로 통합하고, 비공개 섀도 루트를 패치하지 않습니다. _Proof: review_
- **X-FOCUS-8 · MUST** 아무 데도 이어지지 않거나 내부 컨트롤과 겹치는 호스트 탭 정지점을 더하지 않습니다. _Proof: browser_
- **X-FOCUS-9 · MUST** 구성된 대화상자는 처음 포커스를 자기 안에 두고, Tab 과 Shift+Tab 을 그 안에 가두며, Escape 와 Cancel 로 닫히고, Enter 로 기본 액션을 실행하며, 닫힐 때 포커스를 연 요소로 돌려줍니다. _Proof: browser_
- **X-FOCUS-10 · SHOULD** 포커스 트랩이 어떤 컨트롤에 닿지 못한다면 (예: 푸터에 있는 닫힌 섀도의 버튼), 지원되는 통합 방식을 고치거나 지원되는 슬롯에 네이티브 버튼을 넣으세요.
- **X-FOCUS-11 · MUST** 접힌 영역도 그 안의 내용과 상태를 알려 주며, 접기 때문에 해결되지 않은 조치 가능한 오류가 가려지지 않습니다. _Proof: browser_
- **X-FOCUS-12 · MUST** 포커스를 가진 영역을 접으면 포커스는 그 토글로 돌아가고, 포커스된 객체를 지우면 포커스는 다음 의미 있는 액션이나 안정적인 부모 컨트롤로 옮겨 갑니다. _Proof: browser_
- **X-FOCUS-13 · MUST** 백그라운드 요청이 끝났다는 이유만으로 포커스를 옮기지 않습니다. _Proof: browser_
- **X-FOCUS-14 · SHOULD** 접힌 요약은 읽는 사람이 펼칠지 판단하는 데 도움이 되게 쓰세요. 펼친 본문이 이미 그 내용을 보여 준다면 반복되는 요약은 빼고 제목과 상태만 남기세요.

키보드에 안전한 기본 요소를 썼다고 구성된 대화상자가 안전해지지는 않습니다. X-FOCUS-9 는 구성에 관한 규칙입니다.

## 3. 피드백과 읽던 위치

- **X-FEEDBACK-1 · SHOULD** 피드백은 조작한 객체 곁에 보여 주세요. 복사 버튼 옆의“복사됨”표시는 상관없는 전역 알림보다 연결하기 쉽습니다. 토스트는 현재 객체를 넘어서는 변화나, 그렇지 않으면 놓칠 피드백에 어울립니다.
- **X-FEEDBACK-2 · MUST** 성공 표시는 작업이 성공한 뒤에만 보여 주고 (복사라면 클립보드 성공 뒤), 거부는 그 자리에서 처리하되 버튼 기하와 포커스를 유지합니다. _Proof: browser_
- **X-FEEDBACK-3 · MUST** 비동기 피드백은 작업이 시작된 시점의 소스 스냅숏에 속합니다. 복사가 대기 중일 때 콘텐츠가 바뀌면, 이전 완료가 새 콘텐츠를“복사됨”으로 표시하지 않으며, 낡은 피드백은 지우거나 낡았다고 표시합니다. _Proof: unit, browser_
- **X-FEEDBACK-4 · MUST** 스트리밍되는 글자 하나하나를 보조 기술에 알리지 않습니다. _Proof: browser_
- **X-FEEDBACK-5 · MUST** 실시간 로그와 스트리밍 결과는 읽는 사람이 최신 콘텐츠에 있을 때만 따라갑니다. 스크롤해서 벗어나면 따라가기를 멈추고, “최신으로 이동”은 읽던 위치를 빼앗지 않고 따라가기를 되살립니다. _Proof: recording_
- **X-FEEDBACK-6 · SHOULD** 호스트나 고른 컴포넌트가 지원하는 따라가기/고정 계약을 쓰고, 작업과 저장 상태는 애플리케이션에 두세요. 덧붙이기만 하는 읽기 로그는 작업 관리자가 아닙니다.

X-FEEDBACK-3 은 지연만 따로 떼어 시험하지 말고, 중간에 스트림 갱신이 끼어든 상태에서 늦게 오는 성공과 실패를 시험하세요.

## 4. 진행, 실패, 복구

- **X-RECOVER-1 · SHOULD** 스피너만 보여 주지 말고 알려진 단계 (“파일 읽는 중”, “권한 확인 중”, “내보내기 쓰는 중”) 를 이름으로 보여 주고, 타이머 틱마다가 아니라 의미 있는 단계 변화만 알리세요.
- **X-RECOVER-2 · MUST** 백분율은 측정할 수 있는 분모가 있을 때만 보여 줍니다. 경과 시간은 부차적이며 완료 예상치로 제시하지 않습니다. _Proof: review_
- **X-RECOVER-3 · MUST** 오류는 무엇이 실패했는지, 바뀐 것이 있는지, 다음에 무엇을 할지에 답하고, 호스트가 확인할 수 있는 것만 약속합니다. _Proof: review_
- **X-RECOVER-4 · MUST** 저장소가 실패해도 메모리에 있는 입력은 보존하고, 저장 실패는 따로 알립니다. _Proof: unit_
- **X-RECOVER-5 · SHOULD** 자격 증명이 들어 있지 않은 진단 정보는 선택적으로 펼치는 상세에 두세요.
- **X-RECOVER-6 · SHOULD** 실패 하나에는 일관된 복구 하나를 주세요. 행과 토스트를 중복해서 띄우지 마세요.
- **X-RECOVER-7 · MUST** 타임아웃은 롤백의 증거가 아닙니다. 변경을 일으키는 작업은 재시도 전에 커밋되었는지 확인하고, 가능하면 호스트의 멱등성이나 중복 제거 계약을 씁니다. _Proof: unit_

예: “가져오기가 저장 전에 멈췄습니다. 선택한 파일은 그대로 있습니다. 가져오기를 다시 시도하세요.”

| 상황                          | 쓸모 있는 대응                                     | 피할 것                                                 |
| ----------------------------- | -------------------------------------------------- | ------------------------------------------------------- |
| 읽을 수 있는 파일 내용이 없음 | 다른 파일을 고르거나, 지원한다면 그 파일 없이 계속 | 모든 액션이 문서 텍스트를 필요로 하는 것처럼 다루기     |
| 네트워크 중단                 | 입력/부분 출력을 보존하고, 연결되면 재시도         | 폼을 비우거나 애플리케이션 전체를 쓸 수 없다고 선언하기 |
| 권한이나 설정이 거부됨        | 어떤 종류인지 설명하고, 관련 계정/설정으로 연결    | 빠진 권한이나 잘못된 설정에 대한 자동 재시도 루프       |
| 사용자가 취소함               | 취소됨으로 표시하고, 복구 가능한 출력은 유지       | 빨간 실패 스타일이나 멈춘 작업 다시 시작하기            |
| 맥락이 바뀜                   | 낡은 출력임을 표시하고, 현재 데이터로 새로 고침    | 옛 결과를 더 새로운 문서에 조용히 적용하기              |

## 5. 취소, 재시도, 완료는 서로 다른 결과다

- **X-CANCEL-1 · MUST** 둘 다 지원한다면 취소와 제출은 각각 독립적으로 닿을 수 있고, 분명한 접근 가능한 이름과 안정적인 위치를 가집니다. _Proof: browser_
- **X-CANCEL-2 · MUST** 취소 요청은 확인된 취소가 아닙니다. 확인될 때까지 대기 상태를 보여 주고, 클라이언트가 기다리기를 멈출 수만 있을 때는 작업이 멈췄다고 주장하지 말고 그렇게 말합니다. _Proof: unit_
- **X-CANCEL-3 · MUST** 취소를 실패로 보여 주지 않습니다. _Proof: browser_
- **X-CANCEL-4 · MUST** 재시도는 범위를 몰래 넓히거나 목적지를 바꾸지 않고 작업을 다시 보내며, 복원은 편집 가능한 입력만 다시 채웁니다. _Proof: unit_
- **X-CANCEL-5 · MUST** 저장되었거나 적용되었다는 성공은 쓰기가 확인된 뒤에만 알리고, 복구 가능한 부분 출력은 유지합니다. _Proof: unit_
- **X-CANCEL-6 · MUST** 실행 취소는 호스트가 실제로 작업을 되돌릴 수 있을 때만 제공하고, 취소가 이미 끝난 쓰기를 되돌린다고 약속하지 않습니다. _Proof: review_

## 6. 사람이 관찰할 수 있는 것을 확인한다

- **X-VERIFY-1 · SHOULD** 작은 변경에 가능한 모든 테스트를 돌리지 말고, 아래 층을 참고해 결함에 맞는 증거를 고르세요.
- **X-VERIFY-2 · SHOULD** 작업이 외부 작업에 의존한다면 오프라인 경로와 실패 경로를 포함하세요.
- **X-VERIFY-3 · SHOULD** 테스트한 커밋과 남아 있는 외부 전제 조건을 보고하세요.

| 증거 층       | 관련 회귀                                                         |
| ------------- | ----------------------------------------------------------------- |
| 단위/상태     | 취소, 늦은 응답, 범위 식별, 재시도와 복원의 차이                  |
| 통합          | 맥락을 오가도 초안이 남음. 일관된 실패 하나. 오버레이 키보드 경로 |
| 실제 브라우저 | 계산된 치수/기준선/넘침, 대상 상자, 포커스, 비활성 호버, IME      |
| 화면 간       | 영향받는 폼, 검색, 기록, 설정, 가져오기/내보내기, 미리보기, 확인  |
| 변형          | 관련 테마, 폭, 크기 조절, 키보드/거친 입력, 번역/RTL, 모션 줄이기 |
