# packages/docs — the documentation site

Published to **https://ran.chaxus.com** via Cloudflare Pages. 1,393 pages, eight languages:
English under `src/`, every other locale under `<dir>/src/` (`cn`, `ja`, `es`, `pt`, `ko`,
`de`, `fa`), mirrored page for page. `build/langs/locales.ts` is the registry — adding a
language means a row there, not a new hard-coded list somewhere else, and
`pnpm -F docs check:langs` fails on anything a new locale did not get.

The site is generated by **ranpress** (`packages/ranpress`), which supplies the mechanism —
frontmatter, markdown, discovery, writing, verification, the servers. Everything in `build/`
is this site's _policy_: what a page is, what URL it gets, what it looks like. There is no
VitePress, no Vue and no hydration; if you find a note anywhere claiming otherwise, it is
older than the migration.

Most of what is non-obvious here is not the generator — it is the SEO/GEO machinery, the
generated pages, and the Service Worker. Read the relevant section before changing any of
it; each carries a failure mode that is silent.

---

## Commands

```sh
pnpm -F docs dev          # http://localhost:4173 — build, watch the eight prose trees, serve
pnpm -F docs build        # generate into dist/, verify, then assemble llms-full.txt and sw.js
pnpm -F docs preview      # http://localhost:4174 — serve the built dist/, builds nothing
pnpm -F docs verify       # re-run the post-build checks against an existing dist/
pnpm -F docs check:langs  # every locale has every page, and every copy table has every locale
pnpm -F docs verify:design # the ranui design rules, over this site's stylesheets
```

`dev` and `preview` resolve URLs the way Cloudflare Pages does, **including its redirects**.
That fidelity is the point: a generic static server hides exactly the mismatch that once
shipped 904 canonicals naming a URL the host bounces. The resolution table is in
`packages/ranpress/README.md`. Reach for `preview` before a deploy — it serves the real
built bytes and nothing else, so a page that only works because the dev server just rebuilt
it has nowhere to hide.

```

│   ├── build.ts             # the driver: markdown → pages → dist

│   ├── package-facts.ts     # version/licence/formats, read from the workspace
│   ├── nav.ts · links.ts    # sidebar, outline, pager, link resolution
│   ├── verify.ts            # post-build checks — fails the deploy, not the reader
│   ├── dev.ts · preview.ts  # the two local servers
│   └── langs/               # the locale registry, sidebar structure, per-language copy
```

## URLs and the file layout

`content.ts`'s `outFileFor` decides where a page is written, and it must agree with the
canonical the page declares. Cloudflare Pages resolves a request by trying the exact file,
then `<path>.html`, then `<path>/index.html` — and that last case is a **308 to the
trailing-slash form**, not a direct serve.

So a page whose canonical is `/src/ranuts/api` is written to `src/ranuts/api.html`, and a
section index whose canonical is `/src/ranui/button/` is written to
`src/ranui/button/index.html`. Writing the first one into a directory publishes a canonical
that names a URL the host immediately redirects away from; that shipped once, on 904 pages.
`verify` fails the build on any canonical that only resolves through a redirect, so it
cannot drift back silently.

## Two element namespaces in markdown

Pages use custom elements, not components, for anything that is not genuinely interactive.

| Prefix  | What                                                                                                                        |
| ------- | --------------------------------------------------------------------------------------------------------------------------- |
| `r-*`   | Real ranui components, registered by `import('ranui')` in `client/main.ts`.                                                 |
| `ran-*` | This site's own **zero-JavaScript** presentational elements. Styled from `styles/`, nothing registers them, no shadow root. |

`<ran-demo>` is the one that matters: it wraps every live example in the component docs
(~1000 blocks). It is deliberately not a component. Because nothing upgrades it, the demo
markup is in the generated HTML — indexable, and correct with JavaScript disabled — and the
page's own `.prose` rules still reach inside it, which a shadow boundary would sever.

`<ran-demo>` takes `column`, `align="start"` and `align="end"`; anything else is the default
centred row. Note that `align` is the flex **cross** axis, so in the default row it controls
vertical placement — it can never widen a child. To make a demo's contents span the box (a
full-width surface like `r-section`), use `column`, which sets `flex-direction: column` and
therefore stretches horizontally. The section page carried `align="stretch"` for exactly
that intent and got nothing for it, in every language, for as long as the attribute existed.

A `<PascalCase />` tag in markdown is a **build-time** element instead: `components.ts` maps
the name to a function that returns HTML. `HomeCinematic`, `IconGallery`, `GlassPlayground`
and `PackageFacts` work this way. Nothing ships to the client for them.

## Build script conventions (`bin/build.sh`)

**It starts with `set -eu`, and must stay POSIX `sh`.** Without it the script's exit code is
whatever the trailing `echo` returns — i.e. **0 even when the build failed**. That happened:
a broken markdown page failed the build, `mv`/`cat` then failed on the missing `sw.js`, and
the script still exited 0 printing `service work file paths have been generate`. Cloudflare
Pages reads that exit code; a build that cannot fail publishes stale output while reporting
success.

**No bashisms.** `package.json` runs `sh ./bin/build.sh`, and invoking a script through `sh`
**ignores its shebang** — the real interpreter is the system `/bin/sh`. That is bash on
macOS but **dash** on the Cloudflare build image, so anything bash-only passes locally and
fails only in CI. `set -euo pipefail` did exactly that: `set: Illegal option -o pipefail`,
exit 2.

Consequently there is no `pipefail` here. Where a pipeline's first command matters, write
the intermediate result to a file instead of piping — see how the llms-full.txt file list is
built. Verify changes with `/bin/dash -n bin/build.sh`, or run the whole thing under
`/bin/dash`.

If you add a step, assume it will be the one that fails.

## Generated files that are committed

| File                 | Generated by             | Notes                                                                                                                                                                                                                                      |
| -------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/ranuts/api.md`  | `pnpm -F ranuts doc:api` | The full symbol reference. Regenerate after changing ranuts' public exports — the same command also writes `cn/src/ranuts/api.md` (Chinese page chrome, English JSDoc descriptions) and `packages/ranuts/docs/API.md` for the npm tarball. |
| `dist/llms-full.txt` | `bin/build.sh`           | Not committed; rebuilt every time.                                                                                                                                                                                                         |

`src/ranuts/api.md`, `cn/src/ranuts/api.md` and `packages/ranuts/docs/API.md` are in
`.prettierignore` **on purpose**: Prettier rewrites the illustrative snippet
`import { /* … */ } from 'ranuts/utils'` into `import {} from /* … */ 'ranuts/utils'`,
moving the placeholder comment outside the braces. Regenerating is the only source of truth.

Nothing else should write a build timestamp into a tracked source file. There used to be a
`variable/SERVICE_WORK_VERSION.ts` holding `Date.now()`; every build dirtied the working
tree, history collected "update SERVICE_WORK_VERSION" commits, and two builds of the same
commit produced different source trees.

## SEO

`seo.ts` already does the following — verify before assuming something is missing:

- **Extensionless URLs** in canonical, hreflang and sitemap, matching the file layout above
  so nothing points at a redirecting form.
- **Per-page `<meta description>` derived from the page's own first prose paragraph** when
  there is no frontmatter description. Without it all pages share the site description.
- **hreflang alternates, existence-checked**, so a one-language-only page never advertises a
  404 counterpart.
- **`og:` / `twitter:` tags**, and `SoftwareSourceCode` JSON-LD on the ranui/ranuts landings.
- The **home page title** is promoted to the full tagline (otherwise it is just `ran`, since
  `title === site title` suppresses the template).

Site copy is written for SEO/GEO. Don't add decorative taglines to the home page.

`verify.ts` enforces the parts that are checkable — missing or empty title, missing
description, a canonical off-origin, a canonical ending in `.html`, a canonical that does
not resolve back to its own page, a `.html` URL anywhere, dead internal links and anchors, a
built page missing from the sitemap. None of these break a page in a browser, which is
exactly why they need a check.

## AI / GEO surface

Three artefacts, all reachable without JavaScript:

| Artefact            | What                                                                                                                                           | Maintained                                                             |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `public/llms.txt`   | Curated entry map — summary, doc links, entry points, npm/GitHub                                                                               | **By hand.** Refresh when either package's surface changes materially. |
| `llms-full.txt`     | Every `src/` + `<locale>/src/` markdown concatenated, each block prefixed with its canonical URL                                               | Generated per build                                                    |
| `public/robots.txt` | Explicitly allows AI crawlers **including training crawlers** (GPTBot, ClaudeBot, Google-Extended, CCBot, Bytespider) plus the sitemap pointer | By hand                                                                |

Both `llms.txt` and `llms-full.txt` are also linked from `<head>` as `rel="alternate"`. That
is a convention, not a spec — agents normally fetch `/llms.txt` directly; the tags are cheap
insurance.

`llms.txt` is the paragraph a model actually ingests as "what is this project". Treat it as
the highest-leverage prose on the site and keep it current — it had drifted to describing a
ranuts that predated i18n, zip, IndexedDB, Worker and bridge support.

## Service Worker (`public/sw.js`)

Assembled at build time: `bin/build.sh` prepends the precache manifest and
`const VERSION = "<timestamp>"` to the file, and `CACHE_NAME = 'chaxus_ran_' + VERSION`.

Four rules, each of which was previously broken:

**1. The URL stays `/sw.js`. Never put the version in the filename.**
The browser updates a Service Worker by re-fetching **the same URL** and byte-comparing.
When the filename carried the timestamp, a returning visitor's registered `sw<old>.js` no
longer existed on the server, so every update check 404'd — the only remaining update path
was "user loads a page and the inline script registers the new filename". A stable URL
restores the browser's own update path (on navigation, and roughly every 24h) _in addition_
to that one.

Version-in-filename is not needed for freshness either: the version lives in the file's
content, so the bytes change every build, which is exactly what the comparison looks at. And
the browser bypasses its own HTTP cache for the SW main script (`updateViaCache` defaults to
`'imports'`), so a stable URL cannot serve a stale script. `public/_headers` additionally
pins `/sw.js` to `Cache-Control: no-cache` so the CDN edge cannot hold a stale copy either.

**2. The `fetch` handler must be a synchronous function that calls `event.respondWith()`.**
`respondWith` is only valid during the synchronous dispatch of the event; an `async` handler
has already yielded at its first `await`. The handler used to be
`async (event) => { cacheFirst(event.request) }` — async _and_ missing `respondWith`. The
result was a Service Worker that intercepted nothing: install dutifully precached the app
shell and no request ever read it, so users paid the download for zero benefit and offline
did not work.

**3. Strategy is per request type.** HTML navigations (`request.mode === 'navigate'`) are
**network-first with cache fallback** — a docs site must not serve yesterday's prose. Build
output is content-hashed and therefore immutable, so everything else is **cache-first**.

**4. Clone a response _synchronously_, before handing it to the page.** A response body can
only be read once. `updateCache` used to clone inside `caches.open().then(...)`, which runs
a microtask later — by then the caller has already returned the response to the browser and
the body is being consumed, so `clone()` throws `Failed to execute 'clone' on 'Response':
Response body is already used`. This stayed invisible while the fetch handler was broken
(nothing consumed the response); it surfaced the moment interception started working.

`activate` runs `deleteOldCaches()`, which keeps only the current `CACHE_NAME` — that is
what actually evicts the previous deploy's assets, and it is driven by the version inside
the file.

## The client bundle

Deliberately small. Navigation, sidebar, outline, language menu and the mobile drawer are
all generated HTML and CSS — a documentation site that needs script to show its navigation
shows nothing to a crawler, and nothing to a reader on a failed request. What is in
`client/` genuinely cannot be done without it: search, the theme switch, copy buttons, the
scroll-reveal on the landing.

**`@ranui/preview` bundles pdf.js — 1.33 MB.** It loads only when the page actually contains
an `<r-preview>`, checked with `document.querySelector` before the dynamic import. It used
to load unconditionally, which was over half of everything a page downloaded, on every page.

**CSS may hide something only when script is there to bring it back.** `.reveal` sets
`opacity: 0` and an IntersectionObserver adds `.in`; the rule is gated on a `js` class set
before first paint by the theme bootstrap in `page.ts`. Without that gate, JavaScript
disabled meant every landing section below the fold was invisible permanently.

## Design

The site is dressed in ranui's design system. `packages/ranui/docs/DESIGN.md` is the spec;
§11 ("Composition — the page, not the component") is the part that governs pages rather than
widgets, and every rule in it came from a failure on this site. §12 ("Information
architecture") sits one level above it: which shape a dense page should take before any of
§11 arranges it.

`pnpm -F docs verify:design` runs ranui's checker over `styles/` against
`design-baseline.json`, which is a **ratchet**: a violation count that rises fails as a new
violation, and a count that falls fails until it is lowered. The baseline records debt, not
permission — the target for every entry is zero.

Two rules from §11 that this site's stylesheets are built around, because breaking them was
invisible and expensive:

- **The measure governs text, not the column.** `--measure` caps paragraphs and lists;
  tables, fences and demo stages get the full column. Capping the column instead silently
  turned a 762px table into a scroll container inside a 736px cap and clipped its last
  sentence mid-word.
- **Code sits on the prose spine.** A standalone fence has no fill and no horizontal
  padding, so its first character lands at the same x as every paragraph and heading. A
  fence inside a box — a demo's source, a code group — is inset instead, because there the
  spine is the box's.

## Gotchas

| Pitfall                                                                                     | Fix                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Adding a `.md` file to the package root that is not meant to be a page                      | Every markdown file under the root becomes a page. `content.ts` passes `ignoreFiles: ['CLAUDE.md']` and an `ignore` list of non-prose directories — that is why this file is not a route.                                                                                                                                                                                                                                                        |
| Hard-wrapping a Chinese paragraph                                                           | Fine, and required to stay readable. `ranpress` drops the newline between two CJK characters (`collapseCjkSoftbreaks`) and keeps it when either side is Latin. Do **not** "fix" stray spaces by joining lines — if you see one, the collapse broke.                                                                                                                                                                                              |
| A wide markdown table sliding under the right-hand outline                                  | Tables render inside `.table-wrap`, which scrolls; the table itself is `width: max-content; min-width: 100%` so identifiers do not break mid-word into "disable d". Don't render a `<table>` outside the wrapper.                                                                                                                                                                                                                                |
| Adding a page but it never appears                                                          | The sidebar is hand-maintained in `build/langs/structure.ts`. A page with no entry is reachable only by URL.                                                                                                                                                                                                                                                                                                                                     |
| Editing `src/ranuts/api.md` directly                                                        | Generated. Edit the ranuts source JSDoc and run `pnpm -F ranuts doc:api`.                                                                                                                                                                                                                                                                                                                                                                        |
| Expecting the other language trees to update themselves                                     | Every `<dir>/src/` is a manual mirror of `src/`. A new page needs all eight; `pnpm -F docs check:langs` names the missing ones.                                                                                                                                                                                                                                                                                                                  |
| Hard-coding a build-time element's UI text in `components.ts`                               | It renders identically on all eight home pages. Per-language copy lives in `langs/home-copy.ts` (the home page) and `langs/demo-copy.ts` (the glass playground, the icon gallery), keyed by locale directory, and `check:langs` fails on a locale either file is missing. Do **not** add an i18n runtime for this: vue-i18n used to be installed here and was removed — it reached the app only after an `await`, which is why the tables exist. |
| Translating a `<ran-demo>` block's labels inside a component page                           | They mirror the code block printed right under them — `<r-button type="primary">Primary Button</r-button>` has to read the same in both. Same rule for the playground's slider labels, which are `r-glass` attribute names. Only chrome the reader is _told_ in their own language gets translated.                                                                                                                                              |
| Adding `isolation`/`z-index` to the `<ran-demo>` box "just in case" a demo opens an overlay | `ran-demo` stays `isolation: isolate` unconditionally (cheap, contains decorative high-z-index content) but only escalates via `:has(r-modal[open]), :has(r-modal[closing])` — exactly when a real fixed-position overlay is open or fading out. A blanket `z-index` promotes the _whole box_ above the sticky nav for its entire scroll lifetime; that shipped once and painted a static `r-math` demo over the nav on ordinary scroll.         |
| Matching only `:has(r-modal[open])` for that escalation                                     | `close()` removes `open` synchronously but the mask keeps painting for `getTransitionTimeout()` (~0.3s) more. `r-modal` reflects `closing` for exactly that tail — match both, or the still-fading mask repaints under whatever the escalation was holding it above.                                                                                                                                                                             |
| Adding a product switcher / dropdown next to the logo                                       | The nav is deliberately flat: Home · ranui · ranuts · Articles · Doc Editor. A `ProductSwitcher` used to live beside the logo; it needed pixel measuring to sit there and a `pointer-events` hack to be clickable at all. Removed in favour of plain nav items.                                                                                                                                                                                  |
| Adding a custom PWA install prompt                                                          | The site is installable — `public/manifest.json` is linked and the SW is registered — but a `<pwa-install>` element used to be appended on every page load, interrupting reading, and its "remember the dismissal" attribute did not actually stop it recurring. Installation still works through the browser's own affordance.                                                                                                                  |
| Assuming generated output is ignored by tooling                                             | Generated artefacts must be added to `.prettierignore` explicitly, or `lint:prettier` goes red the first time someone runs the generator.                                                                                                                                                                                                                                                                                                        |
