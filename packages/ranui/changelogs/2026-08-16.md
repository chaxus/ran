# Changelog — 2026-08-16

## packages/ranui — new `<r-markdown>`: streaming Markdown renderer

A framework-agnostic Markdown component aimed at AI-chat style output, modelled after
Vercel's [Streamdown](https://streamdown.ai) but built on ranui's own conventions
(closed shadow root, `defineSSR`, builder-constructed DOM, `--ran-*` tokens).

Ships as `components/markdown/` (4 modules), registered as `r-markdown`, exported at
`ranui/markdown`, documented at `docs/src/ranui/markdown/` (en + cn) with a streaming
demo on the demo route.

### What it does

- **Streaming.** `mode="streaming"` (default) runs the text through
  [remend](https://www.npmjs.com/package/remend) — the incomplete-markdown terminator
  extracted from Streamdown — so a half-received `**bold`, `` `code ``, `[link](https://exa`
  or `$$` closes on the fly instead of showing raw markers. The document is then split
  into blocks and **only the block whose source changed is re-rendered**, so a long answer
  never re-parses from the top on every token.
- **Composes the existing renderers** rather than reimplementing them: a closed
  ` ```mermaid ` fence becomes `<r-mermaid>`, `$$…$$` / `\[…\]` / `\(…\)` / ` ```math `
  become `<r-math>`. Both register on demand.
- **Opt-in chrome**: `copy`, `download`, `line-numbers`, `highlight` (shiki), `caret`.
  A bare `<r-markdown>` is clean static output.
- **Sanitized** with DOMPurify — scripts, event handlers, `javascript:` URLs, `<style>`,
  forms and iframes are stripped; task-list checkboxes survive. External links get
  `target` + `rel="noopener noreferrer"`.

### Structure comes from the parser, not from matching text

The first cut re-derived structure with patterns: 14 regex sites deciding what was a
table, where a code fence ended, which HTML tags were still open. That happened because
the pipeline was split in two — block splitting lexed the document and kept only
`token.raw` strings, then rendering parsed those strings _again_. The token information
was thrown away in the middle and had to be guessed back out of the text.

Now the document is lexed **once** by the same configured marked instance that renders it,
and each block renders from its own tokens (`parser.parser(tokens)`). Regex sites: **14 → 3**.

| Was                                                             | Is                                                                                                                                        |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `TABLE_DELIMITER` pattern                                       | `token.type === 'table'`                                                                                                                  |
| `$$`-counting pass to re-glue math split across blocks          | the math extension owns the span, so it is one token                                                                                      |
| `language-…` class matched out of the class attribute           | `classList` + `textContent` (lossless, marked escapes/unescapes)                                                                          |
| two footnote patterns forcing the whole document into one block | deleted — marked core has no footnote tokenizer, so they guarded nothing while collapsing block diffing for any text containing `[^word]` |
| lazy `[\s\S]+?` scanning for a closing `$$` / `\]` / `\)`       | `indexOf`, no backtracking and no length ceiling                                                                                          |
| `<tag>`/`</tag>` counting to find unclosed HTML blocks          | the HTML parser itself, via a sentinel appended inside a throwaway `<template>`                                                           |

The three that remain are the ones where a pattern is the right tool: `CODE_FENCE` (a
verbatim transcription of the CommonMark rule, line-anchored, and only applied to a `code`
token), the `$…$` inline-math rule (real lexical constraints, confined to one line), and a
whitespace split for theme names. The heuristics that _can't_ go away live in `remend`,
which is the correct place for them: its input is by definition not yet valid markdown,
so no parser can do better than guess, and a wrong guess self-corrects on the next token.

Tag counting was not merely inelegant, it was wrong — `<!-- <div> -->` read as an unclosed
tag and swallowed the rest of the document into a single block; `title="</div>"` counted as
two closing tags. The sentinel probe answers all twelve of the cases now under test,
including implied structure (`<table><tr><td>`) that no pattern can see.

### Two real bugs fixed on the way

- **Reference links across blocks** were broken: re-parsing an isolated block could not see
  a `[id]: url` definition living in another one, so `[text][id]` rendered as literal text.
  Lexing once fixes it. Blocks therefore diff on a key of _source + the document's link
  definitions_, since editing a definition can change a block whose own source did not move.
- **`bin/generate-component-api.ts`** attributed a preceding unrelated JSDoc to the first
  accessor with a multi-line comment (its `([\s\S]*?)` body could cross a `*/`). `r-glass`
  and `r-input` had wrong property descriptions in the generated `docs/COMPONENTS.md`.

### Builder over lookup

Everything the component adds to the rendered tree — code-block container, header,
toolbar buttons, table wrapper, `<r-mermaid>` / `<r-math>` — is built with
`@/utils/builder`. `querySelector` count in the component: **9 → 1**.

- The five `querySelectorAll` sweeps in `enhance()` became **one `TreeWalker` pass**
  collecting by tag; nodes are collected before mutation so replacing one cannot move the
  walker.
- Toolbar buttons **bind their own click handler at build time** and close over the code
  they act on, so pressing one needs neither delegation, nor `closest()`, nor reading the
  code back out of the DOM — copy now yields the exact source rather than whatever the
  highlighter left behind. `EventManager` became dead code and was removed.
- `enhance()` **returns the theme-following elements it created**, so retheming works from
  a held reference instead of searching the rendered DOM.
- The one remaining `querySelector` is the HTML sentinel probe, where asking _where_ the
  sentinel ended up also answers whether it survived at all — that is what separates "still
  open" from "swallowed by an unterminated comment".

`DOMPurify` now returns a `DocumentFragment` (`RETURN_DOM_FRAGMENT`) instead of a string:
it already built that DOM while sanitizing, and serializing it just so the component could
parse it a second time cost a full extra parse **per token** for the block being streamed.

### Package size — read before publishing

Four runtime dependencies were added: `marked`, `dompurify`, `remend` (all small) and
**`shiki`**, which is not. Unpacked tarball goes from **30.1 MB** (0.5.0-alpha.1) to
**58.6 MB**; most of the increase is shiki's grammar set.

`vite.config.ts` now exports `singleFileResolve`, shared by the CJS/IIFE bundle and the
standalone per-component IIFE builds, which aliases `shiki` → `shiki/bundle/web` (~50
common languages). These formats cannot code-split, so a plain `shiki` import inlined
every grammar into one file: `dist/index.iife.js` alone was 15.9 MB, now 11.4 MB, and the
whole tarball drops 9.6 MB. The **ES** build is deliberately left on full `shiki`, where
each language is its own lazy chunk and a consumer downloads only what a code fence asks
for — `ranui/markdown` is the entry to prefer, and the docs say so.

That still leaves the package roughly twice its previous size for a feature that is
opt-in behind the `highlight` attribute. Making `shiki` optional would return the tarball
to ~31 MB — `highlight()` already degrades to plain code when the import fails — but it
contradicts `docs/RENDERER_COMPONENTS.md` §1 ("the heavy lib is a regular `dependency`"),
so it is left as an open decision rather than changed unilaterally.

### Known limitations

- **GFM footnotes are not supported** (marked core has no footnote tokenizer); `[^1]`
  renders as literal text. Documented on the component page.
- Single-dollar `$…$` inline math is opt-in via `inline-math`, being ambiguous with currency.
- remend appends closers at the end of the text, so a document with an unclosed `**` _and_
  a later unclosed `` ` `` puts the bold closer inside the code span. This only occurs for
  synthetic input — while actually streaming, the incomplete construct is always last.

### Tests

`test/unit/markdown.contract.test.ts`, 30 cases. Beyond the API contract, each of the
structural regressions above is pinned: the HTML comment, the `</div>` inside a fenced
code block, cross-block reference links (including a definition arriving mid-stream),
block math containing a lone `=` line, footnote-like text, block math having to own its
line, an empty `$$$$`, a 12 000-character formula (no length ceiling), and retheming
through the returned references.
